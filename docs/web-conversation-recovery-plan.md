## 最新实施计划：连接恢复与真实终端统一（2026-09-08）

本节取代下方原结构化聊天主界面方案。用户已批准真实终端方向；当前已完成首个可交付闭环：项目启动后自动 attach 真实 PTY、原始终端输出/输入/resize、断开清理、服务启动就绪和端口冲突保护。多终端标签选择与交互控制权仲裁仍作为后续增强，不属于本次单终端主流程。

### 当前证据与根因边界

- 用户确认此前供应商无法连接；不再将 `cli_turn_failed` 本身作为新的 CLI 启动故障证据。该错误仍存在丢失具体诊断的问题。
- 本机 `127.0.0.1:9090` 被 PID 38108 的安装版主程序监听；绕过代理请求 `/` 和 `/api/health` 均在 8 秒内无响应。
- 21:12:43、21:13:21、21:13:24 日志三次记录 Web listener bind 失败，Windows 错误 10048（端口占用）。PID 14900 是 `cli-manager.exe __daemon`，不能误判为重复主窗口并强杀。
- 已确认故障位于服务生命周期/可用性边界：旧监听仍存在却不响应，新启动无法绑定。尚未证明旧 listener 是被哪个任务或句柄持有，需要有活跃 WebSocket 的进程级复现，不能仅以端口占用断言内部泄漏位置。
- `web_server::start` 在绑定成功前设置 running=true；`status` 只读布尔值。`run_with_shutdown` 在 bind 前已经更新管理员与设备离线状态，失败启动可能影响现有服务数据。修复应落在启动就绪、停止完成及生命周期所有权，而不是浏览器反复重试。
- 当前分支领先 origin/master 20、落后 0；保留现有未提交内容。GitNexus 不可用，使用 codebase-memory 定位并由源码、日志和端口探测复核。

### 实施顺序与验收

1. **服务连接先恢复。** 复现活跃浏览器/设备连接下 stop/restart；明确回收 accept loop、连接任务及 runtime，确认端口释放后才报告停止成功；绑定和初始化完成后才报告就绪。绑定冲突时不先修改管理员或将所有设备标记离线。设置页区分启动中、可用、停止中和失败，显示可理解的错误。验收首页、静态资源、健康检查、登录和 WebSocket，以及连续重启；不以“进程存在/端口监听”作为成功。
2. **统一终端身份和入口。** 浏览器选择项目/Worktree 后列出其真实 PTY 标签，用户选中已有标签即 attach；无标签时沿用桌面启动流程创建，再用返回的 PTY ID attach。一个项目多个标签必须显式选择。历史 CLI Session ID 与 PTY ID 分开处理，历史恢复复用桌面校验及创建入口。主输入不再启动额外 app-server/print 会话。
3. **增加认证终端通道。** 复用设备连接与账号/设备权限，增加会话列表、attach/detach、输入、输出、resize、ACK 和有界回放；终端字节不逐帧写 Web SQLite，不把本机 daemon token 暴露给浏览器，不开放 daemon 监听到公网。复用现有 PTY daemon 回放与背压，但需单独验证经过 Web 转发后的顺序、流控和断线释放。
4. **替换 Web 主界面。** 引入 xterm，采用项目侧栏、终端标签、完整终端区域；保留 CLI 原始布局、颜色、命令及审批交互。移除主流程聊天卡片和 operation 信息大卡片，连接状态压缩为状态栏。手机增加输入辅助、Ctrl/C/Esc/Tab、软键盘与安全区适配，中英文均验证。
5. **处理多端状态。** 同一 PTY 同时可在桌面/Web 查看；同一时刻只有一个交互端控制输入与终端尺寸，显式接管，断线释放控制但不关闭 PTY。桌面缩放与手机缩放不能互相争抢。覆盖最小化/托盘、刷新重连、输出量大、退出/恢复、失效 Worktree、多个标签与会话切换。Local/WSL/SSH 沿用桌面能力边界，未验证环境明确标注，不宣称全覆盖。
6. **真实安装链路验收后打包。** 先跑协议/权限/生命周期回归，再用已恢复供应商完成真实新建、至少两轮回复、Ctrl+C、审批、同一 PTY 双端查看、刷新重连和服务重启验证。打包后再验证安装版资源与入口；记录时间、大小、SHA-256 和未覆盖项。全程保护既有 PTY、用户数据库与凭据，不通过强杀全部进程、清库或换端口掩盖故障。

## 结论与证据边界

保留 CLI-Manager 的 Web 服务、设备 WebSocket、项目/Worktree、文件和 Git 能力；补齐桌面端结构化会话执行、消息同步与手机授权入口。DSH 的关键价值是远程访问复用已有业务 API 和事件流，而非把启动通知当作完整对话协议。

已确认的根因陈述：**当前“收不到回复”的实现缺口位于桌面执行结果到 Web 会话展示的跨层边界：桌面仅发送操作状态和会话标识，协议没有消息事件，浏览器没有助手消息渲染入口，必须贯通生产、传输、持久化与显示四层。**

这不能直接解释截图中的 `cli_start_timeout`。此前“SessionStart 早到被丢弃”的判断只覆盖一种时序，未经实际失败链路验证，不能继续当作已确认根因。

源码证据：

- `src/hooks/useWebDeviceBridge.ts:280` 创建会话；`:298` 在未收到启动事件时超时；`:434` 只有收到 `SessionStart` 才写入 Prompt；`:443` 收到 `Stop` 仅返回 `{tabId, sessionId}`。
- `crates/web-protocol/src/lib.rs` 的 `DeviceToServerFrame` / `BrowserEventPayload` 仅有历史摘要、设备、配对及操作状态，无助手消息/增量事件。
- `apps/web/src/views.tsx:446` 的 `ConversationTimeline` 仅渲染用户 Prompt 和操作卡；操作卡不读取助手正文。
- `src/stores/terminalStore.ts:2085` 直接调用进程管理器创建 PTY，终端组件仅 attach。已排除“必须显示终端组件才能启动 PTY”的推断。
- `terminalStore.ts` 的普通启动命令写入发生在会话登记、持久化之后；因此此前“持久化期间 CLI 已发出启动事件”的解释也不能覆盖这条普通启动路径。Hook 无法绑定时桥接直接忽略事件，是否命中该分支仍需运行记录。
- `src-tauri/src/commands/web_server.rs:96` 的内嵌服务配置校验限定 loopback。电脑上的 `127.0.0.1` URL 不能直接成为手机可用地址。

## 建议实现顺序

### 1. 先闭环一条真实对话

- 为一次请求关联 `operationId / conversationId / turnId` 与内部 CLI session、进程标识；浏览器只获得必要的不透明标识。
- 在桌面执行层记录收到请求、环境校验、进程启动、协议就绪、输入已接收、首个输出、完成/退出等阶段。日志不写 Prompt、回复或密钥。
- 复现当前安装版的失败路径，区分进程未启动、CLI 等待登录/信任确认、Hook 未执行、Hook 无法绑定、输入未接收、输出未发布；超时返回最后完成的阶段。
- Web 新对话优先由桌面 Rust 管理结构化 CLI 会话。Codex 优先复核并复用仓库现有 `codex_app_server_proxy.rs` 的启动配置与协议处理；Claude 选择其可验证的结构化运行能力。代理本身不是完整会话服务，仍需实现会话生命周期和事件消费。
- 就绪依据来自实际协议握手和请求结果；Hook 保留为桌面状态通知，不再作为 Web 首条消息的唯一启动闸门。不得改成固定 sleep 后盲写 PTY。
- 现有交互终端的接管必须明确单一执行归属。同一 CLI 会话已经在终端运行时，不另起一个写入者；支持显式移交或明确提示暂不支持。
- Provider、模型、工作目录、Worktree 配置沿用桌面解析；不因改执行方式丢失现有配置或放宽审批。

### 2. 补齐消息与恢复协议

- 在现有设备/浏览器 WS 上增加会话事件：会话创建、轮次开始、消息增量、消息完成、审批请求、轮次完成/失败。
- 每个事件带会话、轮次、消息 ID 和递增序号。设备重发由服务端去重，浏览器断线后按游标补取；游标过旧时获取快照再接增量。
- 服务端保存已接收的消息与终态；明确缓存正文的数据范围、保留策略和访问权限，不能悄悄把原本摘要缓存扩大为全部历史。
- 新增会话详情读取，历史列表仍用摘要；手机刷新或切会话后可恢复已有正文。
- `TimelineItem` 接入真实助手消息与工具/审批状态；保留操作状态作为辅助诊断。网络已连接、CLI 已就绪、轮次完成分别展示。
- 同会话的并发消息排队或拒绝；请求重试复用幂等键，不能重复启动轮次。手机断网不直接判定桌面任务失败，取消须由执行端确认。

### 3. 手机扫码与授权

- 区分两种关系：现有“桌面实例绑定 Web 服务/账号”和新增“授权手机浏览器访问”。不能把现有设备配对码直接当免登录管理员凭据。
- 桌面展示可访问 URL、二维码有效期、刷新/停止、已授权浏览器、最后活动时间和撤销入口。手机扫码后兑换受限会话，再选择项目进入对话。
- 保留账号登录路径；扫码授权使用独立短期随机令牌，兑换后失效。长期浏览器凭据采用受保护 Cookie，URL 中不保留长期凭据。
- 优先使用用户已有的 HTTPS 服务地址；内嵌服务的局域网开放另行实现绑定、防火墙提示、Origin/Cookie 策略。不能只把绑定改成 `0.0.0.0`，也不把 `127.0.0.1` 编进手机二维码。
- 单独显示浏览器已授权、桌面在线、会话运行状态；撤销时中断该浏览器的活跃连接并拒绝后续请求。
- 公网隧道作为后续可选能力，不自动依赖参考项目运营的中继。

### 4. 手机界面与恢复验收

- 复用当前 `apps/web`，项目/历史使用抽屉，正文占主区域，输入区处理软键盘与 safe-area。
- 触屏发送走显式按钮，中文输入法组合期间不误发；控制触控目标、横向溢出和滚动位置。
- 手机切后台、锁屏、Wi-Fi/蜂窝切换后重建连接并补齐消息；不得因重连自动再次提交 Prompt。
- 界面文案同步中英文，时间继续使用 24 小时制。
