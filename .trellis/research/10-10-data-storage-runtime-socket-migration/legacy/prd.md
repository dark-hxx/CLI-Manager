# Data storage migration runtime socket compatibility

## Goal

关闭所有终端与远程功能后，数据目录切换不再被残留通信端点阻断，同时保留迁移安全与数据保护边界。

## Requirements

- 保留数据库、设置、附件、远程会话及未知普通文件；源目录不删除。
- 仅固定应用所有的 `remote-manager/data/run/api.sock` 且确认为套接字时，允许作为临时运行端点跳过；同名普通文件仍复制，真正链接与未知特殊节点仍拒绝。
- 远程服务或授权过程运行、端点仍监听或状态无法确认时拒绝切换，不自动关闭任务。
- 成功后新服务在新根自行创建端点；失败继续使用旧根，不激活部分目标。
- 沿用 1.4.3，提交后仅构建 NSIS；不推送、安装或修改用户真实目录及进程。

## Acceptance Criteria

- [x] Windows 真实 AF_UNIX 残留端点迁移成功，持久化数据完整，源端点保留，目标无端点。
- [x] 活动/未知路径端点、同名链接与目录联接不被误跳过；普通同名文件照常复制。
- [x] 非空目标、父子路径重叠仍拒绝，复制失败清理临时目标并保留原数据。
- [x] 远程服务启动/运行、微信授权或管理操作并发时预检拒绝，不关闭进程、不保存切换请求。
- [x] 定向 Rust、前端真实函数/中英文文案、类型与 strict 架构检查通过；NSIS 构建退出 0。

## Notes

用户 2026-10-10 已授权修复并打包、新建任务、沿用 1.4.3。现场端点标记为 Windows `0x80000023`，SDK 定义为 `IO_REPARSE_TAG_AF_UNIX`；Bootstrap 保存相同 lastError 且当前根未切换。
