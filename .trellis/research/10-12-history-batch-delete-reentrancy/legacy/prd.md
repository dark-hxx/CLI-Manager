# 历史批量删除防重复执行

## Goal

修复历史批量删除中重复提交导致“找不到会话/删除失败，但另一批仍继续删除”的误导体验。

## Requirements

- 同一 WebView 中单删与批量删除共享执行状态；连点、Enter 连按和关闭后重开历史面板不能启动重叠删除队列。
- 执行期间显示双语删除中状态，禁用确认、取消和再次发起删除；Escape/点击遮罩不得伪装成已取消运行任务。
- 保留整批预检、后台已确认的父子覆盖合并、真实缺行/I/O 失败与部分成功报告，不以吞错替代修复。
- 不改 Rust 删除、备份/回滚、路径与来源校验、历史读取或桌面/Web 终端能力。
- 用户同意新建任务并沿用 1.4.3；验证后先本地提交，再只构建 NSIS，不自动安装或推送。

## Acceptance Criteria

- [x] 原始重复确认的隔离复现仅启动一次删除，只有一次最终提示。
- [x] 执行中重复单删/批删、新组件实例、取消/Escape/遮罩逻辑受控；完成/失败后可重新操作（隔离自动测试）。
- [x] 部分失败、真实会话失效、只读/快照及父子覆盖语义不变。
- [x] 共用确认弹窗未启用等待态的既有行为保持兼容，新增文案兼容 zh-CN/en-US（自动测试；实机切换待人工）。
- [x] 定向测试、类型检查、严格架构检查通过，1.4.3 NSIS 成功且记录来源提交/哈希。
- [ ] 用户安装后的真实批量删除验收。

## Notes

- 基线 master a960d018 工作区干净，与已记录 origin/master 同步；未 fetch/pull/push。
- 隔离复现直接执行真实确认回调与策略，只模拟数据边界，未删除用户历史。现有日志不记录被捕获的 toast，不能据此断言用户当次的具体重复触发动作。
