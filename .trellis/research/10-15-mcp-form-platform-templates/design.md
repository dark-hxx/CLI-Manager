# MCP 通用表单与平台模板设计

状态：用户已评审并授权实施，版本 V1.4.4；基线 `4fbd7c03`。2026-10-15 后续会话已按用户要求运行 task.py start，开始实施。

## 1. 产品结构

沿用设置中的 MCP 列表和现有添加/编辑弹窗，默认显示通用表单。

```text
添加 MCP                                            关闭
[表单 | JSON]                        配置模板
                                    [通用         ▾]
展开选项：通用 / 百智 / 魔搭 / Smithery / Composio
选中平台的简短接入说明                         查看接入说明 ↗

名称 *                         [例如 my-mcp]
连接方式                 [本地命令 stdio | HTTP | SSE]

stdio                           HTTP / SSE
命令 *                          服务地址 *
参数（有序列表）                 请求头（名称 / 值）
环境变量（名称 / 值）
工作目录（可选）

高级设置（默认收起；已有值时可见）
────────────────────────────────────────────────────
添加后可在列表选择 CLI 并保存配置             [取消] [添加]
```

- 首批只有平台模板，不增加 memory、fetch、Context7 等具体 MCP 模板。平台平等展示，不设推荐品牌。
- 模板只是同一张表单的初始值与字段说明；所有预填配置可编辑。通用表单可独立完成任意已支持配置。
- 新建弹窗显示模板入口。编辑既有资源默认显示其表单；不根据 URL 自动套模板，避免修改已有字段。
- 不增加独立模板商店、分步向导、双栏实时预览、联网搜服务或远端连接测试按钮。
- 原有文件导入入口保留。本期不新增粘贴 TOML/安装命令识别；JSON 视图仍处理单个 `mcpServers` 条目。
- CLI 勾选、原生配置预览和“保存 MCP 配置”继续在现有列表。弹窗底部不再复制一套 CLI 勾选。

## 2. 布局与主题

### 2.1 尺寸与密度

- 保留 Mantine Modal。建议最大内容宽约 760px，宽度不超过窗口减 32px；最大高度 90dvh。
- 头部与底部不参与正文滚动；正文唯一纵向滚动容器 `min-height: 0`。JSON 代码区可有自身横向滚动。
- 正文常规内边距 20px，窄窗口 16px；区块间距 20px，标签到输入框 6px，动态行间距 8px。
- 控件高度建议约 34–36px，并随应用字体大小增长；不以固定高度裁掉大字号内容。
- 一列主表单。键值行在常规宽度为“名称约 35% / 值弹性 / 删除”；窄于约 560px 时名称和值上下堆叠，删除按钮仍可见。
- 模板入口使用宽 240px 的 Mantine Select，与表单/JSON 在同一工具栏并排，空间不足时自然换行；标签“配置模板”，默认选中“通用”。展开后依次显示通用、百智、魔搭、Smithery、Composio，选中项带勾选标记；只有五个选项，不增加搜索框或清空按钮。
- 下拉框使用应用 UI 字体和现有主题；菜单通过 portal 显示在 Modal 上方并按可用空间翻转。支持方向键选择、Enter 确认、Escape 关闭、Tab 离开；选中平台后在下方展示简短接入说明及文档链接。
- 增加参数后仅滚动新行至正文可见区域；不滚动整个设置页。底部操作不随行数消失。

### 2.2 视觉语言

复用 `AppMantineThemeProvider` 的 `cliPrimary`、用户字体与字号；设置表单使用 Mantine 控件。

| 元素 | 主题来源 / 视觉要求 |
|---|---|
| 弹窗表面 | 现有设置弹窗的不透明表面与默认边框 |
| 区块 | 主要用间距、标题和细分隔线，不给每组套多层卡片 |
| 输入框 | Mantine 默认输入样式与应用表面、文本、边框 token |
| 模板、连接方式选中 | 主题色文字/边缘 + 可见表面变化 + 选中语义，不只靠淡底色 |
| 补全弹层 | 不透明主题表面，细边框、轻阴影，宽度对齐名称框 |
| 焦点 | 主题色 focus-visible 环；不与错误边框互相覆盖 |
| 删除动作 | 常态低强调，hover/focus 时红色；始终保留可见按钮 |
| 错误 | 字段下方文本 + 错误边框，不能仅变色 |
| 命令/参数/URL/键名 | 可用现有等宽字体；说明及标签用应用 UI 字体 |

- 不硬编码截图的橙色，不新增字体下载、品牌渐变背景或第三套主题。
- 适配现有全部浅/深主题预设；人工至少检查 warm-paper、apple-pure、night-indigo、github-dark。
- hover/选中变化约 120–160ms，以颜色为主，不缩放控件、不移动行；遵循 reduced-motion。
- 中英文共用布局；“工作目录（可选）”、说明链接、错误和 aria 标签均本地化。

### 2.3 弹层、Esc 与焦点归属

沿用已有设置弹层和 Mantine Modal，不新增并行的全局 Esc 监听器。所有关闭入口汇合到同一个编辑器关闭请求，统一处理保存中禁用和未保存更改。

| 当前最上层 | 一次 Esc 的结果 | 下层状态 |
|---|---|---|
| 模板下拉框 / 名称候选 / Monaco 局部菜单 | 收起当前菜单，保留输入 | 编辑器和设置均保持打开 |
| MCP 编辑器，未保存中 | 请求关闭编辑器；如有未保存更改则显示关闭确认 | 设置保持打开 |
| 编辑器关闭确认 | 取消关闭，返回编辑器 | 不连带关闭编辑器或设置 |
| MCP 编辑器保存中 | 不关闭，不假装取消后台保存 | 设置不能响应同一次 Esc |
| 仅设置页可见 | 进入设置既有 requestClose / MCP pending 离开守卫 | 不绕过原生配置未保存提示 |

- 一次 keydown 只作用于一层，退出动画和零时长同步卸载都必须成立；按住 Esc 的 repeat 事件不能继续穿透关闭下一层。监听清理后重新打开行为一致。
- `SettingsModal` 已在 document 冒泡阶段检查 defaultPrevented、isComposing 和 `hasOverlayAboveSettings`，通过原始事件 composedPath 保留已卸载弹窗归属；优先复用，只有定向回归暴露实际缺口才修改。
- 已安装的 Mantine Modal 在 window 捕获阶段处理 Esc，单靠输入框冒泡阶段 stopPropagation 不够。标准 Select/Autocomplete 经 Combobox 提供菜单展开保护，必须保留其目标 props；自定义候选也要同步菜单展开状态，使父 Modal 在该次事件前已停止接管。不要依赖本次按键后更新的状态去补救捕获阶段关闭。
- 如果出现关闭确认，先关闭模板/补全/Monaco 局部浮层，暂停编辑器的 closeOnEscape、遮罩关闭与 trapFocus；确认框独占键盘和焦点，取消后恢复编辑器。不能让两个独立 Modal 的全局监听同时执行 onClose。
- 默认层级基于现有设置 50、MCP 编辑器 80、MCP 保存离开确认 90：编辑器的下拉/补全层显式使用中间层 85，编辑器关闭确认使用 90。集中在 extensions 内定义所需层级，不把整个应用的 z-index 调高，也不使用 9999 抢层。
- Mantine 菜单通过 portal 到不受正文 overflow 约束的容器，设置显式层级、翻转和位移；opaque 主题表面必须完整覆盖下层文本。确认层打开前关闭局部菜单，避免默认 popover 层级 300 压过确认层 90。
- 编辑器保持 Modal 的焦点捕获与焦点返回；模板/候选选项点击仍属于编辑器交互，不触发遮罩关闭。Tab/Shift+Tab 在当前层内循环，关闭回到“添加 MCP”或对应编辑按钮；只在该触发控件仍存在时返回。
- 通过真实 SettingsModal + Mantine + MCP 编辑器的隔离夹具验证键盘与 portal，不以独立 HTML 草图或仅检查 z-index 数值代替；点击命中、菜单边缘裁剪与焦点位置均需验证。

## 3. 表单与动态行

### 3.1 通用字段

- 名称默认空，必填；新建时作为 serverKey 和显示名称。编辑保持现有 key/name 语义与稳定 resourceId。
- stdio：命令必填，参数列表、环境变量列表、工作目录可选。命令和参数分开，表单不执行命令。
- HTTP/SSE：服务 URL 必填，请求头可选；HTTP 对应已有 `streamableHttp`，不是任意 REST 接口。
- 远程配置已有 env、timeout、secretRefs、vendor extras 等值时，必须保留，必要时在高级区域提示“更多配置保留在 JSON”。不因默认表单没显示而清空。
- 不对任意命令自动插入 `cmd /c`。本地与 WSL 的命令、目录解释沿用既有能力，模板不承诺跨环境路径通用。

### 3.2 动态行

- 参数每行一个值，保存顺序等于显示顺序；新增行聚焦新输入框，删除后焦点进入相邻行或“添加参数”。
- MVP 不增加拖拽排序；用户可直接编辑参数行。渲染使用稳定 rowId，不能以数组索引作为身份。
- 环境变量/请求头都是“名称 / 值 / 删除”。新增空行是草稿状态；完全空的未使用行提交时省略。
- 键存在而值为空允许表示显式空字符串；名称空但值非空为错误。模板声明必填的凭据例外：空值阻止提交。
- 参数空字符串可能有真实语义：新建且未编辑的占位行不序列化；已有或明确编辑形成的空参数保留，不使用 `filter(Boolean)`。
- 保存前检测重复键，禁止对象转换时后项静默覆盖前项；请求头名称按不区分大小写检查，env 保留大小写与原始名称。
- 不自动裁剪参数、Key、请求头值或环境变量值；名称字段可去首尾空格，但不能改写用户提供的实际值。

## 4. 名称自动补全

名称框使用可自由输入的 Autocomplete/Combobox；值框不猜测、不补全历史密钥。

| 类型 | 候选来源 |
|---|---|
| 请求头 | 模板专用字段优先；`Authorization`、`Content-Type`、`Accept`、`X-API-Key`、`User-Agent`、`Accept-Language`、`Cache-Control`、`X-Request-ID`、`X-Client-ID`，均需服务支持 |
| 环境变量 | 模板专用变量优先；代理变量、通用 API_KEY/API_TOKEN/ACCESS_TOKEN/BASE_URL，以及常见服务密钥变量；也提供 Authorization 等请求头风格名称，不承诺服务读取 |

- 候选是提示，不代表服务一定读取该字段；用简短说明注明用途。
- 按用户后续反馈，环境变量也提供 `Authorization`、Cookie、X-Auth-Token 等名称建议；选择建议只填写当前行，不把 env 转换成 headers，不把任意 `*_API_KEY` 宣称为所有 MCP 的统一变量。
- 输入即时过滤，本地静态候选无需网络请求；忽略大小写匹配、前缀优先；菜单限高 208px，更多候选可滚动查看，不截断候选数据。
- 已在其他行使用的名称从建议中排除；用户手工输入重复项仍通过校验明确反馈。
- 新增/删除行和 Tab 仅移动焦点，不自动展开候选；点击名称框、输入或方向键才主动展开，空输入优先显示模板建议。无匹配时保留文本，不强制选已有项。（按 2026-10-15 用户截图反馈调整。）
- Down/Up 移动候选，Enter 仅接受当前候选、不提交整个弹窗；Escape 先关闭建议；Tab 正常离开，不能吞掉输入。
- 中文输入法组合期间不接受候选、不触发提交；菜单点击不能因先 blur 而丢失。
- 补全浮层通过受控 portal 显示在 Modal 上方，跟随滚动定位，不被正文容器裁剪；候选菜单自身限高滚动，不增加表单正文的嵌套滚动区域。
- 请求头选择 Authorization 只设置名称。仅当模板明确为 Bearer 时提示值示例 `Bearer <API Key>`，不一律自动修改值。
- 键名、用途说明和候选激活状态可被读屏识别；状态变化不在每次按键播报大段信息。

## 5. 模板行为与候选平台

### 5.1 统一机制

- 模板定义静态数据：id、平台名称、双语说明、官方文档链接、transport、默认配置、字段提示和必填规则。
- 直接在通用字段中填 Key/URL，不另造平台账户页或模板变量表达式引擎。
- 固定地址写默认值；用户专属地址只给 placeholder，placeholder 不是可保存的真实值。
- 选择模板预填连接字段；用户已经自定义的名称优先保留，名称为空或仍是上一模板默认值时使用新默认名。
- 模板不跨品牌复用凭据，应用新模板会清空旧模板的连接凭据。按用户最新截图反馈移除“撤销模板替换”，不再保留模板撤销快照。
- “通用”表示解除模板约束并继续编辑当前配置，不作为隐式清空按钮。
- 下拉选中值始终反映实际应用的模板。无效 JSON 阻止模板切换时，保留 JSON 原文并恢复原选中项，不能显示一个未应用的平台。
- 保存后运行配置独立于模板；后续模板更新不自动重写已创建资源。模板不启动连接、不发现工具、不验证用户账号。

### 5.2 首批候选与资格

| 模板 | 表单预填 | 用户补充 | 边界 |
|---|---|---|---|
| 百智 | HTTP；官方固定 URL；Authorization 行 | `Bearer <自己的 Key>` | 必填凭据，按官方规则计费；只是候选之一 |
| 魔搭 MCP 广场 | HTTP 连接结构；服务地址获取说明 | 从所选服务页面复制实际 URL；必要鉴权按该服务填写 | 不给整个广场编造统一地址，不默认所有服务共享 Key；可切换为该服务实际要求的 SSE/stdio |
| Smithery | HTTP 连接结构；namespace 入口说明 | 已配置连接的实际 namespace MCP URL | 平台当前有 OAuth/连接管理；JSON 保存不等于完成授权；不把 Smithery REST 管理 API 当 MCP URL |
| Composio | HTTP；官方 Connect URL；授权说明 | 在支持的 CLI 中完成账号/应用授权 | 不套用百智 Bearer Key 规则；凭据/授权工作仍由实际 CLI 支持决定 |

以上为方案候选，非已验证上线名单。实现阶段用真实目标 CLI 验证可用路径：静态配置无法完成的平台路径保持待验证，展示品牌选项不代表已完整集成。至少有多个符合条件的平台模板才交付本期，不以百智单独上线满足 R2。

## 6. 表单、JSON、草稿一致性

### 6.1 单一编辑资源

- 每次打开建立资源快照；切换主题、语言、列表刷新、窗口失焦不能替换当前草稿。
- 前端 `McpEditorDraft` 管理字段和稳定 rowId；隐藏元数据保存在原始 snapshot 中。对外仍保存既有 McpResource，不新增数据库表或 IPC。
- 名称、可见连接字段与 JSON 在同一编辑会话内切换，不维护互相覆盖的两个已保存资源。

### 6.2 切换规则

- 表单 → JSON：先序列化行；键冲突/半填行等无法表示时留在表单并定位错误，不静默丢弃。
- JSON → 表单：只有解析成功且为一个服务时更新表单；失败保留原始 JSON 和当前位置，明确错误。
- JSON 模式以 JSON 中的服务 key 为名称来源，顶部名称暂为只读；有效解析后回填，避免同一名称存在两个同时可编辑的来源。
- 未知 vendor fields、timeout、secretRefs 及其他 CLI 扩展字段往返保留；表单只更新其负责的字段。JSON 编辑发生的明确删除应保留删除意图，不能恢复已被用户删除的字段。
- JSON 内同名键必须检出并阻止切换/保存，避免 `JSON.parse` 的 last-wins 静默丢配置。具体使用 Monaco JSON AST/已有依赖能力，不新增自制不完整解析器。
- Monaco 沿用现有 defaultValue + 稳定 model/path/onChange；只在显式切换边界同步，避免按键时 setValue、重建 model 或失焦。
- 切换 stdio/HTTP/SSE 在内存缓存各方式草稿；返回可恢复。提交只包含当前方式有效字段，网络配置不带 command/args/cwd，stdio 不带 url/headers。已存在的合法扩展字段保留。

### 6.3 脱敏密钥

- 已存资源只拿到脱敏值；表单标明“已配置，保持不变”，不得把星号当真实 Key，也不能提供揭示原值按钮。
- 原 key 和路径未改时沿用后端 `preserve_secrets`；显式改值表示替换，删除行表示删除。
- 改名/移动已脱敏键（例如 env.A → env.B）需要重新填写该值，不能把遮罩复制到新路径。env 与 headers 之间移动同理。
- 用户本次手工输入的敏感值可以掩码/显示；JSON 视图会显示本次新输入的值，既有保存密钥仍是脱敏值。
- 不在日志、Trellis 文档、自动补全记录或持久化草稿中保存实际密钥；不新增密钥库或环境变量注入承诺。

## 7. 保存、校验与错误

- 字段 blur 后显示首次错误；之后随输入更新。保存统一校验并聚焦第一处错误，保留所有输入。
- 名称/命令/URL 必填按连接方式判断；URL 允许既有后端支持的地址，包括用户本地服务，不能用纯 HTTPS 校验误拒本地服务。
- 调用现有 Rust validate → onBeforeSave → upsert → onSaved/close 流程。写入错误在当前弹窗内显示，防止重复提交。
- 保存时禁用模板、视图切换、行编辑和关闭；完成后解除。仅保存资源，CLI 开关默认仍全关。
- SSE 与目标 CLI 兼容性以既有 capability/投影校验为准，不新增复杂矩阵；列表应用失败仍显示具体目标的错误。
- 有未保存更改时只在真正关闭弹窗时使用项目已有离开守卫；纯切换表单、主题或模板不频繁弹确认。保存过程中不能离开。
- 成功文案区分“已添加/已保存 MCP”与“已写入 CLI 配置”；新会话加载沿用原有说明，不宣称即时生效。

## 8. 实现边界与文件职责

| 触点 | 建议职责 | 影响 |

## 10. 场景与验收

| 场景 | 预期 |
|---|---|
| 新建 / 编辑 | 新建默认空通用表单；编辑按资源快照恢复，未知字段保留 |
| 空模板 / 平台预填 / 手工修改 | 均可完成；改模板不再提供撤销，不跨平台带旧 Key |
| stdio ↔ HTTP ↔ SSE | 草稿可恢复，提交字段互斥，CLI 能力独立判断 |
| 空行 / 半填行 / 重复键 / 空字符串参数 | 按 §3 与 §6 的显式规则处理，不靠对象覆盖 |
| 中英文输入 / IME / 键盘 | 名称补全可选、自定义可用、无 Enter 误提交 |
| 菜单展开 / 编辑器 / 关闭确认 / 仅设置 | Esc 只作用于当前层；关闭确认取消后可继续编辑 |
| Esc repeat / 零动画同步卸载 / 保存中 | 不连续穿透关闭，保存中设置仍保持打开 |
| Portal / 遮罩 / 滚动底部 / Monaco 局部菜单 | 浮层可点击不遮挡更高层，背景不抢焦点 |
| 补全接近滚动底部 / 小窗口 / 大字号 | 浮层翻转定位，底部操作可达，不出现横向整页滚动 |
| 亮/暗/系统主题切换 | 候选、焦点、选中与错误清晰，草稿无重置 |
| JSON 错误 / 未知扩展 / 脱敏字段改名 | 保留草稿、明确阻止损失、重新填写必要密钥 |
| 窗口失焦 / 最小化 / 托盘后恢复 | 不自动提交、连接或丢草稿；恢复不抢终端焦点 |
| 分屏 / 多会话 / Workspan / focus mode / 侧栏折叠 | 全局设置弹窗行为一致；终端布局无数据依赖，不更改会话 |
| Windows / WSL / Bash / 项目 Worktree | 保持既有 Home 和项目应用路径，不自动跨环境改写命令或路径 |
| Hook 装/未装 | 配置表单独立工作，不能以 Hook 状态替代 MCP 保存状态 |
| 保存失败 / Home 变化 / stale revision | 后端既有保护继续生效；输入保留，不制造成功 |

产品验收按 frontend quality 约束由人工运行桌面；独立草图的浏览器检查只能证明草图，不证明 Tauri 功能或远端服务可用。
