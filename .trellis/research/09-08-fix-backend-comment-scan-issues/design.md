# Design: 后端扫描问题修复总线

## Boundaries

父任务不直接承载产品实现。两个子任务共享一份观察项台账和验证门禁，但分别提交、检查和回滚，避免高确定性缺陷被长期加固工作阻塞。

## Data Flow

`observations.md` 候选项 → 证据/严重度分类 → GitNexus 影响分析 → 失败测试或复现 → 根因修复/加固 → 定向验证 → 跨域检查 → 台账关闭。

## Compatibility

默认保持 IPC、序列化、数据库 schema、文件格式和 UI 文案不变。若某项必须改变契约，回退到规划阶段并拆出独立子任务。

## Rollback

每个工作流按独立小批次修改；验证失败时仅回退该批次的自有改动，不触碰主工作区注释或其他任务文件。
