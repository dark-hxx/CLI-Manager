# Issue #184：历史会话自动命名与原文视图精简

关联 Issue：https://github.com/dark-hxx/CLI-Manager/issues/184

## Goal

降低历史会话回溯成本：列表标题能快速辨认会话主题；原文视图优先呈现用户与模型的正文，同时保留工具调用、工具返回、思考过程和系统上下文的查看能力。

## Execution Order

本任务分为两个严格串行的阶段：

1. **阶段 A（当前唯一实施范围）**：新增独立“对话”视图、完整保留现有“原文”视图，并修复历史列表需要重复点击才能打开详情的问题。
2. **阶段 B（后置，当前禁止实施）**：小模型自动命名。只有阶段 A 完成实现、通过质量检查并由用户验收后，才能重新审查自动命名方案并进入实施。

阶段 A 不得新增自动命名的数据库字段、设置项、模型请求、cc-switch 调用或后台任务。阶段 B 的需求和设计仅作为后续规划记录，不属于阶段 A 的完成条件。

## Confirmed Facts

- 当前本地历史标题已经优先取首条用户消息并截断到 80 字，缺失时才退回首条消息或会话 ID（`src-tauri/src/commands/history.rs:4052`）；SSH 历史使用相同的“首条用户消息 → 首条消息 → 会话 ID”规则（`src-tauri/history-core/src/lib.rs:288`）。
- 当前已经支持手动别名；展示优先级是 `alias > source title`（`src/stores/historyStore.ts:1371`），所以自动标题不能替代或覆盖手动别名。
- 当前 `HistoryMessage` 只有 `role/content` 等扁平字段（`src-tauri/src/commands/history.rs:463`、`src/lib/types.ts:585`）。虽然工具结果会被归类为 `tool`，但混合消息中的正文、工具块、reasoning 和系统注入尚无稳定的分段类型契约。
- 原文页已有长消息折叠、搜索命中强制展开和独立工具详情页（`src/components/history/SessionDetailPane.tsx:111`、`:290`、`:1055`），可以复用，不需要另建第二套历史详情页。
- cc-switch 已能只在 Rust 后端读取供应商真实配置，并对 Claude Messages、OpenAI Chat Completions / Responses 发起真实模型请求（`src-tauri/src/commands/ccswitch.rs:648`、`:715`、`:747`）；密钥不需要暴露给前端。
- 项目另有 OpenAI 兼容的命令建议请求、超时和响应解析实现（`src-tauri/src/commands/command_suggestion.rs:105`），标题生成不应复制一套无关 HTTP 细节。

## Requirements

### 阶段 A · R1 独立“对话”与“原文”视图

- 保留当前“原文”页签及其完整消息顺序、长内容折叠、编辑/删除/插入能力，不改变其作为审计与原始记录入口的职责。
- 在“原文”之前新增独立“对话”页签并设为详情默认页：只突出用户正文与助手正文；工具调用、工具返回、reasoning/thinking、系统注入和来源元数据按相邻区段折叠。
- 不增加“精简/完整”二级切换，也不持久化模式；顶层页签已经能清楚表达两种职责，避免用户进入原文后再操作一次。
- 折叠区显示类别和数量，点击后原位展开；现有工具详情页继续提供结构化工具诊断。
- 会话内搜索命中隐藏内容时自动展开对应区段并定位；时间线、Diff、工具页跳转到隐藏消息时也必须展开并定位。
- 来源没有记录 thinking/tool payload 时不伪造内容，只展示实际可解析内容。

### 阶段 A · R2 列表单击打开详情

- 非批量选择模式下，会话卡片除树展开按钮、删除按钮和其他显式操作按钮外，整行都是打开详情的点击目标。
- 单次点击立即切换选中态并加载右侧详情；加载中显示目标会话标题和 loading 状态，不要求再次点击。
- 快速连续点击不同会话时只展示最后一次点击的详情；旧请求返回不得覆盖当前详情。
- 批量选择模式继续整行切换勾选，不打开详情。
- 根因修复落在列表事件边界：当前只有卡片内部内容按钮绑定 onOpenSession，卡片留白、padding、树形缩进和行尾区域点击无效（src/components/history/HistoryListPane.tsx:1020、:1115）。Store 已在首次有效点击时同步设置 activeSessionKey 并用请求序号防止旧请求覆盖（src/stores/historyStore.ts:2511），不是详情加载需要多次请求。

### 阶段 A · R3 结构化消息契约

- 后端为消息补充显式 part/kind 分类，至少覆盖 `text`、`tool_call`、`tool_result`、`reasoning`、`system`、`metadata`、`unknown`。
- 保留现有扁平 `content` 兼容搜索、编辑、转换和旧快照；新“对话”视图优先消费结构化 parts，现有“原文”视图保持兼容。
- 老快照或暂未分类的来源按角色兼容：user/assistant 文本保留在对话区，tool/system/unknown 进入详情区，不能因缺少新字段导致空白。
- 本地与 SSH 历史使用同一分类语义；只读远端不得因为视图变化尝试修改远端文件。

### 阶段 A · R4 国际化与可访问性

- 所有新文案同步支持 `zh-CN` 与 `en-US`，并继续兼容项目现有 `zh-TW` 回退/覆写机制。
- 页签、折叠摘要和整行点击具有正确的 aria/键盘语义；键盘可打开会话和展开折叠区。

### 阶段 B（后置）· R5 标题来源与优先级

- 展示优先级固定为：手动别名 > 自动生成标题 > 当前来源标题 > 会话 ID。
- 自动生成标题只写 CLI-Manager 自己的元数据，不修改第三方原始会话文件。
- 关闭自动命名时保持现有标题行为不变。

### 阶段 B（后置）· R6 小模型失败策略

- 自动命名默认关闭，显式选择 cc-switch Claude/Codex 供应商配置后才允许启用。
- 失败、超时、限流、供应商删除或响应不合法时保留当前来源标题，不自动无限重试。
- 只发送首轮可见对话正文，并明确披露外部请求与费用。

### 阶段 B（后置）· R7 自动触发边界

- 以历史索引观察到首个完整回合作为触发条件，不依赖 Hook。
- 只自动处理启用后的新会话；旧会话和失败会话允许手动生成/重试。
- 多会话使用有界单队列，避免并发风暴和重复计费。

## Scenario Matrix

### 阶段 A（当前）

| 维度 | 必须覆盖的行为 |
|---|---|
| 窗口焦点/最小化/托盘 | 视图渲染与列表单击不依赖窗口焦点；重新聚焦后不需要额外点击 |
| 多会话/Workspan/分屏 | 快速点击不同会话时最后一次请求获胜；不会串用上一会话详情 |
| Local / WSL / SSH | 使用一致的消息 part 分类；SSH 历史继续只读 |
| 主仓库 / Worktree | 以现有 session key 隔离详情；同 session id 的不同路径不互相覆盖 |
| Hook 安装/未安装 | 对话视图读取历史索引，不依赖 Hook 是否安装 |
| 父会话/子任务树 | 点击卡片打开详情；树展开按钮只展开/折叠，不触发详情请求 |
| 批量选择开启/关闭 | 开启时整行切换勾选；关闭时整行单击打开详情 |
| 新快照/旧快照 | 有 parts 时精确分类；无 parts 时按 role 保守回退且不显示空白 |
| 搜索/跨视图跳转 | 命中折叠内容时展开并定位；message index 保持现有坐标 |
| 来源内容类型 | Claude/Codex 结构块优先精确分类；其他来源走兼容分类 |

### 阶段 B（后置）

自动命名的焦点、并发、Hook、新旧会话、离线和别名竞态矩阵，待阶段 A 验收后重新收敛，不参与本轮实现。

## Acceptance Criteria

### 阶段 A 完成条件（当前）

- [ ] 打开任意会话详情时默认进入独立“对话”页签；“原文”页签继续保留当前完整消息和编辑能力。
- [ ] “对话”页签只突出用户/助手正文，其他可获得内容可在原位置展开。
- [ ] 搜索和跨视图跳转能定位到默认折叠的内容。
- [ ] 非批量模式点击会话卡片任意非操作区只需一次即可切换选中态并加载详情；快速点击不同会话时最后一次点击获胜。
- [ ] Local、WSL、SSH 历史在同一内容类型上具有一致的折叠语义。
- [ ] 新旧快照都能显示；缺少 parts 时不出现空消息。
- [ ] 新增界面在 `zh-CN`、`zh-TW`、`en-US` 下无硬编码文案，时间格式保持 24 小时制。

### 阶段 B 完成条件（后置，不参与阶段 A 验收）

- [ ] 默认设置下不发起任何标题模型请求，历史标题与当前版本一致。
- [ ] 开启并选择有效供应商后，新会话首轮完整对话被索引时只生成一次短标题。
- [ ] 模型失败时保留原来源标题且不会循环重试；手动别名始终优先。
- [ ] 首次开启不会自动处理已有历史；旧会话可手动生成。

## Out of Scope

### 阶段 A 明确排除

- 自动命名的数据库迁移、设置界面、模型请求、cc-switch 接线、后台队列和测试。
- 对标题优先级或现有标题生成逻辑做任何改动。

### 整体任务排除

- 在 CLI-Manager 内新建完整的通用供应商管理系统。
- 自动发现供应商支持的全部模型或跨协议自动降级。
- 修改第三方 CLI 的原始会话标题或同步回 cc-switch。
- 对来源未记录的思考过程、工具参数或工具返回进行推断重建。

## Deferred Decision

- 小模型产品定位不阻塞阶段 A。阶段 A 验收完成后，再决定是否采用“默认关闭、显式配置后启用、失败无损回退”的阶段 B 方案。
