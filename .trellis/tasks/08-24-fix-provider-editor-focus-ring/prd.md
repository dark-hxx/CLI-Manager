# 修复供应商编辑关闭后的焦点残留

## Goal

移除供应商详情关闭后，供应商目录行被重新聚焦而显示的残留焦点环；关闭后的焦点必须仍留在可访问的供应商设置页内。

## Confirmed Facts

- 用户截图中的细矩形位于供应商卡片的主按钮，而不是卡片的 `selected` 样式。此前已在目录关闭详情时移除 `selected` / `aria-current` 状态，截图仍存在。
- Mantine `Modal` 默认 `returnFocus={true}`。详情弹窗打开时会记录当前的供应商行按钮，关闭后会再次将焦点放回该按钮；该按钮的 `.ui-focus-ring:focus-visible` 因而绘制矩形焦点环。
- 编辑表单是叠在详情弹窗上的独立 Modal；表单关闭后应继续回到下方详情弹窗，不应改变该嵌套焦点行为。
- 首次替代方案把焦点放到 `tabIndex={-1}` 的页面根节点；浏览器仍会为该程序聚焦元素绘制默认黑色轮廓，因此该落点不可用。

## Requirements

- 关闭供应商详情弹窗后，目录中的供应商行不得因 Modal 焦点回退而保留焦点环或看起来仍被选中。
- 详情弹窗关闭后，将焦点转移到现有且可见的目录 surface 导航控件，不能让焦点落在 `body`、已卸载的弹窗元素或新的整页焦点轮廓上。
- 保留详情 → 编辑表单 → 详情的嵌套焦点返回行为；不通过全局隐藏或删除 `.ui-focus-ring` 来处理。
- 不改变供应商选择缓存、详情数据、编辑保存、删除、排序或键盘打开卡片的既有语义。

## Scope

- `NativeProviderDetailModal` 的关闭焦点策略。
- `NativeProviderSettingsPage` 中详情关闭后的稳定焦点落点。
- 覆盖该契约的聚焦回归检查，以及 `TEMP` 发布记录和功能清单。

## Out of Scope

- 修改所有 Mantine Modal 的默认焦点策略。
- 修改供应商卡片的选中样式、通用 `.ui-focus-ring` 样式或目录选择缓存。
- 重构表单、详情内容或供应商数据/IPC 链路。

## Acceptance Criteria

- [ ] 鼠标、Escape 或遮罩关闭供应商详情后，供应商列表行没有残留的焦点环或“已选中”外观。
- [ ] 详情关闭后的焦点位于现有目录 surface 导航控件；按 Tab 可继续进入设置页控件，焦点不会丢到页面主体或产生整页黑色边框。
- [ ] 编辑表单取消或保存后仍返回详情弹窗；随后关闭详情时才执行新的目录页焦点落点。
- [ ] Claude、Codex 与 Grok Build 三个供应商类型共用同一关闭行为。
- [ ] 聚焦回归检查、TypeScript 检查和前端构建通过；`CHANGELOG.md` 与 `docs/功能清单.md` 使用 `TEMP` 记录本次修复。

## Notes

- 根因修复的边界是 Modal 的焦点生命周期，而非供应商行的表现样式。
