# Web 设备连接状态同步修复

## 已确认问题及根因

- 用户截图：设备实际可用，设置 -> 远程连接 -> Web 设备连接仍显示“正在连接”。
- 只读查询运行中的正式版和开发版 daemon，均返回 `running=true, connected=true, paired=true`，没有连接错误。
- 根因位于 Rust 状态查询到 React 消费者的同步边界：独立 daemon 不发送 Tauri 状态事件，现有全局 bridge 每 3 秒查询到权威状态却不传播，设置页只保留初次查询/启动响应。
- 修复落在共享 IPC 状态入口：发布查询及命令的状态快照，设置页订阅该来源，复用全局轮询；不根据网络地址或浏览器可用性猜测在线。

## 实施及验收

1. 新建有界共享状态来源，保留最近一次快照，合并重叠查询；按请求顺序拒绝旧回执，重复快照不通知。
2. 状态查询及保存、启动、停止、重启、清除配对回执通过共享入口；保存仍返回原始响应以同步提交版本的表单。
3. 设置页先订阅再查询；Tauri 事件只触发权威查询，卸载移除订阅；保留草稿版本保护及配对过期刷新。
4. 定向测试覆盖 daemon 无事件更新、断开/重连、已连接未配对、保存期间编辑、迟到回执、切页/语言和查询错误恢复。
5. 运行桌面 TypeScript 检查、独立严格架构检查，更新 V1.5.1 两份交付记录。

## 场景矩阵

| 维度 | 覆盖与边界 |
| --- | --- |
| 后台模式 | 独立 daemon 为主要故障场景；无 helper 的 Tauri 路径保持，事件视为失效通知 |
| 连接状态 | 未配置、停止、连接中、已连接未配对、配对成功、网络断开、自动重连、手动启停/重启 |
| 时序 | 重叠查询合并；旧查询/启动回执不能覆盖已收到的较新快照；失败保留已知状态，不虚构成功 |
| 窗口焦点 | 当前/其他窗口/失焦不决定状态；每个 WebView 独立订阅该 profile 的 IPC 查询 |
| 最小化/托盘 | daemon 继续运行；UI 定时器可能受宿主节流，恢复后依现有全局查询更新，不承诺后台实时刷新 |
| 设置页面 | 打开、切页、关闭、重新打开；订阅不管理远程连接，不新增页面轮询 |
| 分屏/多会话/Workspan | 设备级状态，目标 pane 和 CLI 会话无关；全局 bridge 的定时器及连接生命周期保留 |
| 侧栏/专注模式 | 不影响设备级状态，状态显示继续使用现有设置组件 |
| 本地/WSL/Worktree/Hook | 状态来自设备 transport，不依赖 shell、目录类型或 Hook 安装；相关执行逻辑确认无关 |
| 正式版/开发版 | 不同 WebView/profile 独立；不合并 clientId，不读取凭据进入前端 |
| 语言 | 沿用 zh-CN/en-US 已有停止/连接中/等待配对/在线文案；时间格式不修改 |
