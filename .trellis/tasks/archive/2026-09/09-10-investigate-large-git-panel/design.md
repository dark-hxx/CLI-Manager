# 技术方案（已批准并实施）

## 边界和数据流
保留 Rust/SSH 状态接口、完整 GitFileChange[] 和 Git 写操作语义；修改集中在 src/features/git 的 store、树组件与面板统计。

1. Transport 返回完整快照，按项目路径 + repoId + transport.contextKey + 生命周期代次验证归属。
2. 同身份快照相等时保留 changes/tree/选择集合引用；避免重复建树及重复通知。
3. 将树构造提取为领域内纯模块。小列表同步执行；大列表（初始阈值 5000）交给 Worker 建树，返回前再次验证代次。Worker 错误时采用可让出主线程的分批构造；不截断数据。Worker 生命周期和 fallback 必须单测。分组、排序、节点路径与当前行为兼容。
4. 将两分区标题及展开树行扁平化为一个虚拟列表，共享现有 Content 滚动容器，使用已安装 @tanstack/react-virtual。行 key 含分区与真实路径；目录压缩沿用现有规则；保留单一滚动条和分区顺序。
5. 行组件只绘制当前行，不再递归挂载。改成精确 selector，图标和静态目录汇总缓存。目录计数按树/选择集合代次聚合一次；点击批量操作时才收集完整后代路径。不能把业务操作范围限制到虚拟可见行。
6. 面板摘要由 memo 化聚合提供，分支状态/提交输入等更新不重复扫描完整列表。

## 刷新合并
同身份最多一个状态查询在途；期间收到新刷新标记 dirty，完成后最多补一次合并刷新。写操作后的刷新必须等到写之后发起的那次查询，不能复用写之前的快照而提前返回。多个调用者共享 drain promise，错误和 finally 释放在途状态。

项目/子仓库/Transport/reset 改变使旧生命周期代次失效，涵盖 A→B→A。退出当前面板后不应用旧结果；不要求取消无法取消的原生 Git 命令。连续文件事件可以持续要求下一轮，但不得并发或累积每事件一个查询。保留 silent 与显式加载/错误展示区分。

## 兼容与风险
- 不新增依赖、IPC 字段或数据库迁移；本地/WSL/SSH 共用改进。
- 不修改后端扫描，现有日志继续区分后台慢查询和 UI 阻塞。如 UI 修复后的 trace 证明原生扫描有独立瓶颈，另记录证据后扩展方案。
- 重点风险：虚拟行回收时右键/拖拽焦点、目录三态、隐藏面板初始零尺寸、Worker 过期响应、操作后刷新等待。
- 保持中英文标签和 24 小时时制；如不加文案，也需要双语交互巡检。
- 回滚以本任务改动为单位恢复树/刷新实现；不得覆盖已有 Pi 终端或其他文档修改。

## 规划决策
选择虚拟化和有界计算，完整保留变更数据。仅默认折叠无法覆盖根目录大量文件；截断列表会损害批量操作完整性。无需重新设计后端分页协议来解决已确认的前端瓶颈。
