# VS Code 式工作区布局控制实施计划

## 阶段 0：基线和影响确认

1. 确认当前分支同步状态、保留用户已有未提交修改。
2. 阅读 `.trellis/spec/guides/fix-triage-guide.md` 中需求场景和回归要求。
3. 使用 GitNexus 对将修改的符号执行 upstream impact；索引不可用时以契约文档和源码调用点补充分析。
4. 建立本阶段只涉及前端布局、设置偏好、i18n、测试和两份交付文档的边界。

## 阶段 1：布局状态和迁移

目标：让新入口拥有稳定、可迁移、可持久化的状态。

1. 修改 `src/lib/workspaceLayout.ts`：升级版本、增加项目侧栏停靠侧和两个可见性字段、补齐默认值和迁移规则。
2. 检查 `settingsStore` 和 `syncSettings`，确保新字段沿用现有 preferences 持久化链路。
3. 为迁移、默认值、非法值回退和恢复默认增加纯函数测试。
4. 运行布局相关测试和 `npx tsc --noEmit`。

阶段验收：旧设置可读取，新设置可保存；没有修改 PTY、数据库或 IPC。

## 阶段 2：工作区可见性接线

目标：隐藏/恢复区域时不破坏已有内容和会话。

1. 在 `TerminalWorkspaceFrame` 接入辅助面板区域可见性，隐藏时不渲染占位。
2. 在 `WorkspanTerminalLayout` 接入 Tab 栏可见性，隐藏时保留 Workspan 状态和会话。
3. 在 `TerminalTabs` 统一处理“打开具体辅助面板前确保区域可见”的行为。
4. 保持辅助面板左右停靠、项目侧栏左右停靠和两侧宽度拖拽；操作栏随辅助面板同侧停靠到外缘，并同步调整其侧向弹窗。
5. 检查终端无活跃会话、Workspan 未启用/无 Tab 和窄窗口的降级状态。
6. 运行静态契约测试、类型检查和已有终端布局测试。

阶段验收：三个区域可以独立显示/隐藏，恢复后具体面板和终端会话仍在。

## 阶段 3：标题栏控件和菜单

目标：完成 VS Code 式主界面入口。

1. 新增 `WorkspaceLayoutControls`，拆分按钮、菜单项和 tooltip/aria 文案职责，避免将交互逻辑堆进 `WindowTitleBar`。
2. 将控件挂载到 `WindowTitleBar`，明确非拖拽区域和原生窗口按钮边界。
3. 快速按钮接入项目侧栏已有 toggle 事件、辅助区域可见性和 Tab 栏可见性；无 Workspan Tab 时禁用第三个按钮并避免无效写入。
4. `...` 菜单接入项目侧栏左右停靠、辅助面板左右停靠、上下 Tab 和恢复默认。
5. 增加中英文 i18n 文案和键盘/无障碍状态。
6. 为窄窗口、设置页和会话历史页补充样式规则，保持页面背景边界。

阶段验收：用户不进入设置页即可完成显示/隐藏、位置切换和恢复默认；窗口控制与拖拽正常。

## 阶段 4：移除旧设置入口

1. 从 `SidebarSettingsPage` 删除 `WorkspaceLayoutSection` 的挂载。
2. 删除无调用方的旧布局卡片组件，清理仅由该组件使用的文案和导入。
3. 更新原有静态测试，使其验证标题栏入口和新状态链路，不再要求设置页存在布局卡片。

阶段验收：设置页不再出现旧布局控制，不存在两个入口造成的状态分叉。

## 阶段 5：完整验证和交付记录

1. 执行 `npx tsc --noEmit`。
2. 执行相关 Node 测试；必要时执行完整前端测试和构建。
3. 检查 `git diff --check`、变更文件范围和单文件长度/职责。
4. 使用 GitNexus `detect_changes()` 检查实际影响范围，仅允许布局、设置、i18n、测试和交付文档相关变更。
5. 更新 `CHANGELOG.md` 的 `V1.3.9` 条目和 `docs/功能清单.md` 对应的布局/终端板块。
6. 向用户报告验证结果和剩余风险；未经用户明确要求不自动提交。

## 回滚边界

- 状态迁移和 UI 控件可独立回退；
- 不涉及数据库迁移、IPC 和 PTY，回滚不需要数据恢复；
- 保留旧位置字段，出现异常时可优先关闭新增可见性控制并恢复原有布局渲染。
