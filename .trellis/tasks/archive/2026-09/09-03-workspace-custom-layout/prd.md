# Issue #248：VS Code 式工作区布局控制

## 1. 目标

将当前通过“设置 -> 侧边栏 -> 工作区布局”调整位置的方式，改为类似 VS Code 的主界面布局控制：用户在应用顶部直接看到布局操作入口，切换后立即生效并持久化，不需要进入设置页。

本阶段只调整布局控制入口、状态模型和工作区交互，不改变已经完成的背景行为：

- 开启“背景铺满工作区”时，工作区主区域、左右工作区侧栏和 Tab 终端区域使用同一背景；
- 关闭时，仅终端 xterm 区域显示背景；
- 设置页和会话历史页保持不透明，不展示工作区背景；
- 设置页和会话历史页顶部应用操作栏保持不透明。

版本目标：`V1.3.9`。

## 2. 已确认的现状

- `WindowTitleBar` 已负责应用顶部标题栏和窗口控制，但目前没有工作区布局控制组。
- 项目侧栏由 `Sidebar` 管理，已有折叠、展开、宽度记忆和 `SIDEBAR_TOGGLE_REQUEST_EVENT`，不应再创建一套重复的可见状态。
- `TerminalWorkspaceFrame` 已负责终端中心区、辅助面板和操作栏的布局；辅助面板已有左右停靠和宽度拖拽能力。
- `WorkspanTerminalLayout` 已负责 Workspan Tab 栏的顶部/底部布局；Tab 栏位置已有持久化设置。
- 终端辅助面板的具体内容由 `TerminalTabs` 管理，打开的 Git、统计、历史回放、文件、供应商等面板状态不应因隐藏面板区域而丢失。
- `workspaceLayout` 已作为偏好设置持久化，默认辅助面板停靠右侧、Workspan Tab 栏位于顶部。
- 当前设置页的 `WorkspaceLayoutSection` 是布局入口，但卡片式位置选择不符合本阶段的 VS Code 式交互目标。

VS Code 的参考交互是：标题栏提供常用界面元素的快速切换，并通过右侧的 Customize Layout 菜单处理位置和布局重置；布局变化即时生效并保留。参考：[VS Code Custom Layout](https://code.visualstudio.com/docs/configure/custom-layout)。

## 3. 已确认的方案 A

### 3.1 主入口

在 `WindowTitleBar` 增加独立的 `WorkspaceLayoutControls` 控件组，位于应用拖拽区域和原生窗口按钮之间。控件组自身及其子元素必须标记为非拖拽区域，不能影响窗口拖拽、最小化、最大化和关闭。

提供三个常用快速控制：

1. 项目侧栏显示/隐藏；
2. 终端辅助面板区域显示/隐藏；
3. Workspan Tab 栏显示/隐藏。

控件使用图标、悬浮提示、`aria-label` 和选中状态表达当前状态，不增加新的常驻文字占位。

### 3.2 更多布局菜单

标题栏提供 `...` 菜单，菜单项包括：

- 项目侧栏：停靠左侧 / 停靠右侧；
- 终端辅助面板：停靠左侧 / 停靠右侧；
- Workspan Tab 栏：位于顶部 / 位于底部；
- 恢复默认布局。

位置切换只改变布局，不关闭当前已打开的具体面板，不重建 PTY 会话，也不改变终端内容。

### 3.3 保留的交互

- 辅助面板宽度继续使用现有 sash 拖拽；
- 项目侧栏宽度继续使用现有宽度记忆；
- 现有终端工具栏、操作栏和面板入口继续可用；
- 从操作栏打开任一辅助面板时，如果辅助面板区域被隐藏，先自动显示区域，再打开目标面板；
- 隐藏辅助面板区域时保留 Git、统计、历史回放、文件、供应商等具体面板的打开状态，恢复显示后回到原来的内容。

### 3.4 设置页调整

移除设置页中的 `WorkspaceLayoutSection` 及其布局位置卡片。设置页仍可保留主题、背景和其他终端配置，但不再作为工作区布局的控制中心。

## 4. 状态和持久化要求

保留现有位置字段，并在 `workspaceLayout` 中增加可见性字段：

```ts
interface WorkspaceLayoutSettings {
  version: 3;
  projectSidebarSide: "left" | "right";
  terminalSidePanelSide: "left" | "right";
  workspanTabBarPosition: "top" | "bottom";
  terminalSidePanelVisible: boolean;
  workspanTabBarVisible: boolean;
}
```

兼容要求：

- 旧版只有 `version: 1/2` 或缺少新增字段的设置，项目侧栏迁移为左侧，两个可见性字段均为 `true`；
- 非法位置值和非法可见性值回退到默认值；
- 恢复默认布局将项目侧栏设为左侧、辅助面板设为右侧、Workspan Tab 栏设为顶部，并显示这两个区域；
- 恢复默认布局不清除项目侧栏的历史宽度，不清除终端会话，不清除具体辅助面板状态；
- 项目侧栏的停靠侧加入 `workspaceLayout`，折叠状态和宽度仍复用现有记忆；
- 新增字段随现有 preferences 同步，不新增数据库表、迁移、IPC 命令或第三方依赖。

## 5. 需求边界

### 5.1 本阶段包含

- 标题栏布局快速控制组；
- `...` 布局菜单；
- 项目侧栏左/右停靠，且右停靠时仍支持从靠近终端的一侧拖拽调整宽度；
- 辅助面板和 Workspan Tab 栏的可见性状态；
- 旧布局设置迁移和偏好持久化；
- 设置页布局卡片移除；
- 中英文界面文案、提示和无障碍标签；
- 小屏、全屏、设置页、会话历史页和无 Workspan 状态下的降级处理；
- 对应单元/静态契约测试和类型检查。

### 5.2 本阶段不包含

- 任意拖拽到任意区域的自由 Dock；
- 浮动窗口、多窗口、多显示器、网格分屏或自定义布局快照；
- PTY 生命周期、终端会话数据、数据库结构和 IPC 契约调整；
- 面板内容本身的重构；
- 背景图片加载、透明度算法或设置页/历史页背景规则变更；
- 用新的设置页入口替代标题栏入口。

## 6. 场景清单

实现和验证必须覆盖以下场景：

- 窗口焦点变化、窗口拖拽区域、最小化/最大化/关闭按钮不受影响；
- 普通窗口、最大化窗口、窄窗口和高 DPI 缩放下标题栏控件不挤压原生按钮；
- 项目侧栏展开、折叠、恢复展开后宽度保持；
- 项目侧栏左停靠切换右停靠，切换后折叠状态、宽度和项目操作保持；
- 辅助面板右停靠切换左停靠，左右切换后宽度和打开内容保持；
- 辅助面板隐藏后从操作栏打开 Git/统计/历史/文件/供应商面板；
- Workspan 未启用、已启用但无会话、单 Tab、多 Tab 时隐藏和恢复 Tab 栏；
- Workspan 未启用或当前没有 Workspan Tab 时，第三个快捷按钮禁用并说明原因，不产生无效写入；
- 上下 Tab 栏切换不改变终端会话和中心区滚动/尺寸；
- 设置页和会话历史页打开时，背景和顶部应用操作栏保持不透明；
- 开启或关闭“背景铺满工作区”时，布局控制不改变背景作用域；
- 刷新应用、重新启动应用、旧版本设置迁移和损坏偏好回退；
- 中文、英文切换后按钮、菜单、提示和 `aria-label` 均有对应文案，英文时间格式仍为 24 小时制。

## 7. 验收标准

- 用户无需进入设置页，即可在顶部完成三个区域的显示/隐藏。
- 用户无需进入设置页，即可切换项目侧栏左右停靠、辅助面板左右停靠和 Workspan Tab 栏上下位置。
- 每次切换在当前界面即时生效，刷新或重启后状态保持。
- 隐藏区域不会销毁会话、面板内容或已保存宽度；恢复后可继续使用。
- 设置页不再显示旧的布局位置卡片。
- 标题栏控件不破坏窗口拖拽和原生窗口按钮。
- 背景铺满开关的既有两种模式和设置/历史页不透明规则全部保持。
- `zh-CN`、`en-US` 文案完整，类型检查、相关测试和构建检查通过。
- 单文件按职责拆分，布局控件、状态迁移、布局渲染和样式不集中堆入单个超长文件。
