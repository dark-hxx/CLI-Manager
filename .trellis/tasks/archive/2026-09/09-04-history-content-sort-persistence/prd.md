# 会话历史内容排序与操作记忆

## Goal

让用户在打开会话历史详情时，可以按时间/产生顺序查看内容，也可以切换到倒序快速查看最新内容；用户选择的排序方向在切换会话、关闭并重新打开历史工作区以及应用重启后仍然有效。Codex 会话同时优先使用可用的线程名称，并保持 AI 标题与手工别名的优先级。

## Confirmed Facts

- 历史详情由 `src/components/history/SessionDetailPane.tsx` 统一挂载多个页签：`conversation`（对话）、`transcript`（原文）、`timeline`（过程）、`canvas`（画布）、`context`（上下文）、`changes`（变更）、`tools`（工具）、`subtasks`（子任务）。
- 当前请求明确点名需要排序的页签为：对话、原文、过程、变更、工具、子任务；画布是空间布局视图，上下文是统计卡片/趋势视图，暂不应被默认当作时间序列列表修改。
- 对话和原文使用 `SessionDetailPane` 内的虚拟列表；当前详情消息按 `activeSession.messages` 的原始索引正序展示，搜索、编辑/插入/删除、批量选择和跨视图跳转都依赖原始 `messageIndex`，排序不能改变该坐标。
- 过程、变更、工具、子任务分别由 `SessionTimelineView`、`SessionFileChangesView`、`SessionToolDiagnosticsView`、`SessionSubtaskTreeView` 渲染；它们目前各自消费 `SessionProcessModel` 或历史结构化数组，并存在按原始消息索引/时间/文件名的内部排序规则。
- `src/stores/settingsStore.ts` 已通过 `tauri-plugin-store` 持久化用户偏好，并采用 `Settings` 类型、默认值和加载时迁移/校验；历史侧栏宽度已使用同一机制记忆。该需求不需要数据库迁移或后端 IPC 变更。
- `src/components/HistoryWorkspace.tsx` 当前把详情页签状态保存在组件本地，并在切换会话时重置为“对话”；排序偏好若要求跨会话/重启记忆，应进入设置存储，而不能只放在详情组件本地。
- 项目要求新增用户可见文案同时覆盖 `zh-CN` 与 `en-US`，并保持现有 `zh-TW` 回退/覆写行为；时间展示继续使用 24 小时制。
- Codex 官方的本地 `CODEX_HOME/session_index.jsonl` 使用 `id`、`thread_name`、`updated_at` 记录线程名称；当前仓库的 Codex 历史解析主要从 rollout 内容生成首条用户消息标题，尚未把匹配的 `thread_name` 纳入统一显示标题。
- 当前历史标题已有统一解析链：手工 alias 优先于 AI 生成标题，再回退到来源标题/会话 ID；AI 生成标题保存在 `history_generated_titles`，并已同步用于历史列表、详情和搜索结果的显示。
- Local、WSL 与 SSH 历史都通过统一的会话身份/来源实例链路进入历史视图；标题读取必须沿用该身份边界，不能用裸会话 ID 在不同机器或来源间误匹配。

## Fundamental Constraints

- 排序只改变视图投影，不重排或修改后端消息、原始历史文件、搜索索引、编辑定位和跳转坐标。
- 筛选后的列表仍应先完成同一筛选，再按当前方向排序；切换方向不得丢失筛选条件、选中状态或当前视图职责。
- 没有可靠时间戳的条目使用现有稳定顺序/消息索引作为 tie-breaker，不能因排序产生随机抖动。
- 空状态、加载中、无时间戳、旧快照、本地/WSL/SSH、主仓库/Worktree、父会话/子任务都必须保持可用。

## Requirements

- R1. 点名的六个详情页签提供清晰、可访问的“正序/倒序”切换入口；切换后当前页签立即按对应方向渲染。
- R2. 对话与原文按原始消息序列的正序/倒序展示，但每条消息仍保留原始 `messageIndex`；搜索定位、编辑/插入/删除、批量删除、跨视图跳转和加载更多不能因视觉倒序失效。
- R3. 过程、变更、工具、子任务的记录列表与对话/原文一样按当前页签方向整体反转；文件变更内部的文件名排序、工具统计数量等不具备时间序列语义的内容保持原有规则。
- R3a. “过程”反转全部可见事件；“变更”反转变更记录节点但保留节点内文件名顺序；“工具”反转结构化调用、错误线索和疑似事件列表但不反转聚合计数；“子任务”反转子任务记录并保持“主会话”根节点固定。
- R4. 用户的排序操作被持久化，并在重新打开历史工作区、切换会话和应用重启后恢复；每个纳入范围的详情页签独立保存自己的方向。
- R5. 每个纳入范围的详情页签的排序偏好对所有会话共用；切换会话时沿用该页签的已保存方向，不为每个会话创建独立配置。
- R6. 首次使用默认正序：对话/原文从第一条消息开始，过程/变更/工具/子任务沿用当前已有顺序；用户切换后按各页签保存的方向恢复。
- R7. 排序范围仅包含对话、原文、过程、变更、工具、子任务；画布与上下文保持现有空间布局和统计语义，不增加排序控制。
- R8. 详情页签栏旁提供一个“当前视图排序”切换按钮；它显示当前页签的正序/倒序状态，切换立即刷新当前页签并写入持久化设置，切换页签时读取对应页签状态。
- R9. 新增文案走 `src/lib/i18n.ts`，覆盖 `zh-CN` 与 `en-US`，兼容现有 `zh-TW`；排序按钮具有 tooltip、`aria-label`、`aria-pressed` 或等效状态语义及键盘操作。
- R10. 切换方向后，无搜索定位或跨视图跳转目标时将滚动位置重置到新顺序的起点；存在目标时按原始消息索引重新定位。切换会话时定位到当前方向的起点。
- R11. 排序方向切换先立即作用于当前界面；若持久化写入失败，不回滚当前界面，下一次启动继续使用最近一次成功保存的方向，失败信息仅写入调试日志，不打断用户操作。
- R12. 对 Codex 会话读取与会话 ID 匹配的 `session_index.jsonl.thread_name`，并将其作为统一历史名称候选；名称候选应同时覆盖历史列表、详情标题和搜索结果，不能只在单一视图生效。
- R13. 标题候选按“手工 alias > 有效的 AI 生成标题 > Codex `thread_name` > 现有来源标题/首条用户消息 > 会话 ID”解析；AI 标题存在时优先于 `thread_name`，手工 alias 始终不被自动标题覆盖。
- R14. `thread_name` 标题能力覆盖 Windows 本地、WSL 与 SSH 远程 Codex 会话；对应索引不可访问、条目缺失或身份不匹配时，不影响会话加载，并按既有标题链路回退。

## Scenario Matrix

| 维度 | 必须覆盖的行为 |
|---|---|
| 视图 | 对话、原文、过程、变更、工具、子任务分别切换并保持正确排序；画布/上下文按最终范围处理 |
| 方向 | 正序、倒序；重复点击幂等；刷新数据后顺序稳定 |
| 分页 | 正序从头部向尾部加载；倒序从尾部向头部加载；切换方向后重新计算窗口，不重复、不漏项 |
| 会话 | 首次打开、切换不同会话、重新打开历史工作区、应用重启后恢复偏好 |
| 消息操作 | 搜索命中、上一条/下一条命中、跳转到消息、编辑/插入/删除、批量选择、加载更多 |
| 数据质量 | 有/无时间戳、相同时间戳、旧快照、空数据、长列表/虚拟列表 |
| 来源与路径 | Local、WSL、SSH；主仓库、Worktree；父会话与子任务 |
| UI 状态 | 窗口焦点变化、最小化/托盘、展开/折叠侧栏、中文/英文界面 |
| 持久化 | 设置读取缺失/非法、写入成功、写入失败后继续操作与下次启动恢复 |
| 标题来源 | Codex thread name 存在/缺失/失配、AI 标题 pending/succeeded/cleared、手工别名与来源标题回退 |

## Acceptance Criteria

- [ ] 六个点名详情页签均能在正序与倒序之间切换，当前可见条目立即反映选择。
- [ ] 对话/原文倒序展示时，搜索、定位、编辑/插入/删除、批量选择和加载更多仍指向正确的原始消息。
- [ ] 过程/变更/工具/子任务的时间序列条目方向正确；非时间序列的统计卡片或文件名排序不会被错误反转。
- [ ] 切换方向或会话后列表定位到当前方向起点；搜索命中和跨视图跳转仍能定位正确的原始消息。
- [ ] 排序偏好在切换会话、关闭再打开历史工作区和应用重启后按约定恢复，旧设置缺失或非法时安全使用默认值。
- [ ] 持久化写入失败时当前界面仍立即切换且不崩溃；下一次启动使用最近一次成功保存的方向。
- [ ] Codex 会话存在有效 `thread_name` 时，历史列表、详情和搜索结果使用该名称；缺失或失配时安全回退。
- [ ] AI 生成标题存在时优先于 Codex `thread_name` 展示，标题生成/清除后的各视图显示保持一致。
- [ ] Windows 本地、WSL、SSH 远程 Codex 会话均按来源实例和会话 ID正确匹配 `thread_name`；索引不可用时不崩溃、不串名。
- [ ] 标题刷新时，已打开详情、历史列表和搜索结果在下一次统一刷新或标题操作完成后使用最新候选；不要求额外的后台文件监听。
- [ ] 有/无时间戳、相同时间戳、旧快照、空状态、Local/WSL/SSH、Worktree、父/子任务场景无崩溃、错位或随机顺序。
- [ ] 新增文案在 `zh-CN`、`zh-TW`、`en-US` 下可用，按钮具备键盘和屏幕阅读器可理解的状态。
- [ ] 完成前端类型检查、相关测试、GitNexus 变更范围检查，并更新 `CHANGELOG.md`（版本待定，未提供时使用 `TEMP`）和 `docs/功能清单.md`。

## Resolved Decisions

- 排序方向按详情页签独立记忆，但不区分会话；用户在一个会话中调整“对话”方向后，其他会话的“对话”页签沿用同一方向。
- 首次使用默认正序；未写入新设置的旧用户不会看到内容方向变化。
- 仅纳入六个顺序型视图；画布和上下文不纳入。
- 六个视图的时间序列记录统一遵循当前页签方向：正序旧记录在前，倒序新记录在前；记录内部的非时间序列排序不随之反转。
- 过程、变更、工具、子任务按上述规则整体反转；用户确认不需要为这些视图另行定义不同的反转策略。
- 排序是完整内容序列的正序/倒序：倒序时最新消息/事件显示在顶部，而不是只反转当前已加载的一页；分页、虚拟滚动和加载更多必须继续覆盖完整序列。
- 当前详情 IPC 已返回完整消息数组，因此倒序消息优先从数组尾部取可见窗口，加载更多时向更早索引扩展；正序继续从数组头部开始，加载更多向数组尾部扩展。若后端未来提供消息分页，仍须保持尾部优先语义。
- 切换方向或会话时默认定位到新序列起点；若存在搜索命中或跨视图跳转目标，则优先按原始消息索引定位目标。
- 排序设置写入失败不阻塞当前视图，也不回滚内存状态；持久化层保留最近一次成功值，后续启动以该值为准，并仅记录调试日志。
- “记住用户的操作”本任务仅指六个详情视图的排序方向；当前详情页签不持久化，重新打开历史工作区或切换会话时仍默认进入“对话”。
- Codex `thread_name` 纳入标题候选；手工别名优先于 AI 生成标题，AI 生成标题优先于该候选。
- `thread_name` 在本地、WSL、SSH 三类 Codex 会话中都尝试读取；读取失败或无法匹配时沿用现有回退标题，不阻塞历史功能。
- 标题源文件外部发生变化时，在下一次历史刷新或重新打开详情时重新解析；应用内部的 AI 标题生成/清除和 alias 修改完成后立即重算当前内存视图。

## Out of Scope

- 不修改历史后端数据、原始文件、数据库 schema、IPC command 契约或消息索引定义。
- 不改变历史列表（左侧会话列表）的会话分组/更新时间排序；本任务只调整列表、详情和搜索结果的标题候选，不调整列表顺序。
- 不把画布节点重新布局，也不反转上下文统计图的数据口径。
