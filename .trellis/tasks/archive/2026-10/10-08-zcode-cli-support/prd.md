# ZCode CLI 类别接入

## Goal

在新建、编辑和克隆项目的 CLI 工具选择中增加官方 ZCode，并通过现有项目终端启动。

## Confirmed scope

- 用户在 2026-10-08 审阅后明确要求“直接进行实施”“仅是增加一个 CLI 类别”，本次按该范围收窄。
- 用户确认本机没有安装 ZCode；本轮验证类别、图标和现有启动拼接，不执行真实 ZCode TUI。
- 版本使用 `V1.4.2`，当前 `pr-273-local` 无上游，保留此前 CLI 优先排序及隐藏项改动。
- 官方来源与入口已核对，证据保留在 `research.md`；默认命令为 `zcode`。

## Requirements

- 在统一 `CLI_TOOL_DESCRIPTORS` 中增加 ZCode，使用现有 Zhipu 品牌图标，不在项目弹窗复制完整工具列表。
- ZCode 追加到现有可见工具之后，保留 Claude、Codex、Pi、Grok、DSH 前五顺序及四项隐藏规则。
- 复用现有命令、参数、Shell、环境变量和项目／Worktree 路径传递；不增加包装器、安装器或版本检查。
- 标签／项目图标通过既有工具识别正常显示；不注册未实现的历史来源、图片粘贴、供应商、Hook 或 MCP/Skills 能力。
- 品牌名 `ZCode` 在中英文界面一致；交付更新 CHANGELOG 与功能清单的 V1.4.2 记录。

## Acceptance

- [x] 统一工具描述和图标包含 ZCode，项目候选列表自动显示且顺序正确。
- [x] 现有启动拼接保留 ZCode 命令和参数，元数据及图标识别可用。
- [x] 类型检查、相关现有回归和独立严格架构检查通过。
- [x] V1.4.2 两份交付记录准确；明确本机未安装，实际 TUI 待用户验证。

## Out of scope

ZCode 专用命令解析、终端恢复画面策略、原生会话恢复、历史／统计、Hook、供应商、MCP/Skills、自动安装，以及真实 WSL/SSH 验收。提交与推送按用户后续明确指令执行。
