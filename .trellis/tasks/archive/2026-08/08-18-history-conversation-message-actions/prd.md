# 历史会话对话消息操作按钮

## 目标

让历史会话“对话”页中每条可见消息具备与“原文”页相同的消息操作入口，避免用户为了复制、编辑、插入或删除而切换视图寻找同一条消息。

## 已确认事实

- `src/components/history/SessionDetailPane.tsx` 的“原文”页由 `HistoryMessageCard` 渲染消息操作栏：复制始终可用；编辑、插入、删除仅对本地可编辑消息可用。
- “对话”页由 `ConversationRowCard` 渲染；每个对话行一一对应一条原始消息，并保留原始消息索引，因此能够复用既有操作回调。
- 对话页只显示 user/assistant 的可见文本 part；系统、工具、推理和空消息不会产生对话卡片。
- SSH 与快照会话保持只读，不能因本需求暴露写操作。
- 现有 `history.edit.*` 翻译键和消息操作样式可复用，无需新增用户可见文案。

## 范围

- 在“对话”页可见消息卡片上显示与“原文”页一致的复制、编辑、插入、删除入口及无障碍标签。
- 复用既有可编辑性判断、复制、编辑、插入、删除和确认链路；不新增 IPC、持久化结构或依赖。
- 保持消息原始索引、搜索跳转、虚拟列表高度测量与隐藏 part 的既有行为。

## 不包含

- 不让对话页显示被过滤的系统、工具或推理消息。
- 不改变 SSH/快照只读策略。
- 不修改历史消息解析、后端命令、数据库或国际化词条。

## 已确定交互

- 复制在“对话”页直接执行，与“原文”页使用相同的完整消息内容来源。
- 用户点击编辑或插入后，先通过既有编辑警告闸门；获准后自动切换到“原文”页，并打开该原始消息已有的编辑或插入表单。
- 删除继续走既有确认与删除链路，不额外切换视图。
- 批量选择模式沿用“原文”页行为，隐藏单条操作栏，不新增并行的单条修改入口。

## 验收标准

- [ ] 非批量选择状态下，对话页每条可见消息显示与原文页相同的操作按钮、tooltip 和 aria-label。
- [ ] 本地可编辑消息可使用复制、编辑、插入、删除；不可编辑、SSH 与快照消息仅显示复制。
- [ ] 编辑或插入仅在既有编辑闸门获准后切换到“原文”页，并定位到同一原始消息的表单。
- [ ] 批量选择模式下，对话页不显示单条操作栏，保持既有批量删除交互。
- [ ] 操作不会改变消息索引、搜索定位、虚拟滚动或对隐藏 part 的过滤。
- [ ] `npx tsc --noEmit` 通过，并手动验证中文和英文界面下按钮行为与原文页一致。
