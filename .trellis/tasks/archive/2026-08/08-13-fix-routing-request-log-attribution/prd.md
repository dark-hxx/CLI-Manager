# 修复路由请求日志会话归属

## Changelog Target

`[TEMP]`

## Goal

修复历史用量分析请求日志中路由记录无法关联项目和会话、路由与本地会话重复统计的问题，并精简数据来源文案、优化汇总卡片响应式布局。

## Requirements

- “本地会话记录”改为“本地会话”，“路由真实响应”改为“路由”，同步更新 `zh-CN`/`en-US`。
- 路由记录通过已有 `session_id` 与本地 `request_logs` 精确关联项目、历史文件和会话。
- 归属完成后“项目 / 会话”列展示项目名与真实会话 ID，并恢复“查看会话”能力。
- 归属失败不得被静默吞掉；历史同步 IPC 应向调用方返回归属错误。
- 路由真实响应与同一来源/会话/模型/输出的本地会话记录只计一次；兼容路由输入含缓存、本地输入与缓存分列的 Token 语义。
- 五张请求日志统计卡片在窗口缩小时保持同一行，列宽和内容随容器收缩。
- 不修改路由请求协议或既有 IPC 参数；通过追加迁移更新统一用量视图。

## Acceptance Criteria

- [x] 路由记录状态显示“路由”，会话回退显示“本地会话”。
- [x] 可匹配 `request_logs.session_id` 的路由记录写入 `project_key` 和 `file_path`，状态为 `resolved`。
- [x] 无匹配项的非空路由会话 ID 标记为 `unattributed`。
- [x] SQL 归属错误会使 `history_sync_request_logs` 返回错误，不再静默展示未知项目。
- [x] Rust 回归测试、`cargo check`、`npx tsc --noEmit` 通过。
- [x] 路由与本地会话的缓存分列 Token 语义可正确去重，列表与汇总仅保留路由记录。
- [x] 历史概览与请求日志使用一致的路由替代匹配规则。
- [x] 五张汇总卡片在同一行自适应收缩。

## Notes

- 根因：归属 SQL 的相关子查询 `ORDER BY` 不能解析外层 `usage_records.started_at_ms`；同步入口又丢弃了错误。
- 现有数据库抽样：204 条 Codex route 记录均有会话 ID，且全部能精确匹配 `request_logs.session_id`，但均停留在 `pending`。
- 根因修复落在 `src-tauri/src/usage.rs` 与同步错误边界；前端只修改已有 i18n 文案。
- 重复根因：统一视图要求四项 Token 列完全相等；Codex 路由响应的输入包含缓存，而本地历史已拆成输入与缓存列，导致同一请求永远无法匹配。参照 CC Switch 的“代理权威、会话回退、统一查询过滤”设计，在统一视图和历史概览采用同一缓存归一化匹配。
