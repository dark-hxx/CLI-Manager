# 支持 Windows 便携版与自定义数据目录

## Goal

为 Issue #199 提供 Windows 便携版，并允许用户指定 CLI-Manager 数据根目录，使当前默认保存在 `%USERPROFILE%\\.cli-manager` 下的全部内容可以随程序目录或自定义目录整体迁移。

## Background

- 当前稳定数据根目录为 `<home>/.cli-manager`。
- 用户需要的是“可迁移的数据根目录”，不是仅增加一个免安装压缩包。
- Changelog Target：`V1.3.5`。
- Issue：`#199`，交付提交使用非关闭式关联 `Refs #199`。

## Requirements

### R1 Windows 便携分发

- 提供无需安装的 Windows 便携版产物。
- 便携版默认使用程序所在目录下的 `data` 子目录，目录内直接保存原 `<home>/.cli-manager` 下的全部内容。
- “程序所在目录”由便携版身份自动决定，不作为手动切换选项。

### R2 可配置数据根目录

- 安装版和便携版都支持选择自定义目录作为 CLI-Manager 数据根目录。
- 安装版恢复默认时使用 `<home>/.cli-manager`；便携版恢复默认时使用程序所在目录下约定的相对数据目录。
- 用户选择的目录本身就是数据根目录，不再自动追加 `.cli-manager` 或 `data` 子目录；原本应写入 `<home>/.cli-manager` 的内容直接写入该目录。
- 数据目录配置必须在数据库和主设置文件初始化之前可解析，不能依赖待重定向目录中的 `settings.json` 或 `cli-manager.db` 自举。
- 数据目录入口放在“设置 → 通用”页面底部，展示当前模式与实际路径，只提供“选择自定义目录”和“恢复默认目录”，并在变更后明确提示重启生效。

### R3 数据范围

- “全部数据”仅指当前 `%USERPROFILE%\\.cli-manager` 目录下由 CLI-Manager 管理的所有内容，包括数据库、Store 文件、日志、缓存、附件、备份及其他子目录。
- 不管理、不迁移、不重定向 `.claude`、`.codex`、WSL Home、项目目录或其他外部 CLI 数据。

### R4 迁移与兼容

- 未启用便携模式且未指定自定义目录时，继续使用 `<home>/.cli-manager`，保持现有安装版兼容。
- 用户复制便携程序与其数据目录到另一位置后，应用应能继续读取原数据。
- 切换数据根目录不得静默覆盖目标目录中的已有数据。
- 选择自定义目录或恢复本版本默认目录时，由用户明确选择以下操作之一：
  - 迁移当前数据并重启切换；
  - 不迁移数据，直接重启并使用目标目录；
  - 取消操作。
- 自动迁移仅允许写入空目标目录；目标已有内容时禁止自动合并或覆盖，只允许用户确认后直接使用目标目录。
- 无论是否迁移，数据根目录切换都必须通过完整重启生效。

### R5 路径安全与可诊断性

- 自定义目录必须在 Rust/Tauri 边界校验并规范化。
- 目录不可创建、不可写或配置损坏时，应用必须给出明确错误，不能静默回退到另一数据目录造成数据分叉。

### R6 单实例

- 安装版与便携版继续共用现有全局单实例域，不能同时运行。
- 第二个启动的版本只唤醒已运行实例，不创建独立数据库连接或 PTY daemon。

### R7 运行中任务保护

- 存在终端或后台任务时，禁止迁移或切换数据根目录。
- 设置页明确提示用户先关闭全部终端和后台任务后再重试。
- 不自动终止任务，不在旧 daemon 仍运行时启动新数据根目录对应的 daemon。

### R8 更新策略

- 安装版继续使用现有应用内下载、安装并重启流程。
- 便携版保留更新检查与新版本提示，但不调用 Tauri 安装器。
- 便携版点击更新时打开 Release 页面，由用户下载并替换新版便携 ZIP。

### R9 发布范围

- 沿用当前 Windows 发布架构，V1.3.5 首期提供 Windows x64 便携 ZIP。
- 便携 ZIP 包含主程序、运行所需资源、辅助可执行文件和便携标记文件，不包含安装器。

## Confirmed Technical Facts

- `src-tauri/src/app_paths.rs:54` 当前将数据根目录固定解析为 `<home>/.cli-manager`；数据库、Store、日志、Provider、历史缓存和备份主要从该入口派生。
- `src-tauri/src/lib.rs:710` 附近的启动链路在创建 Tauri Builder 和前端 Store 之前就解析数据库与日志目录，因此数据根目录必须由启动期 Bootstrap 机制确定。
- `src-tauri/src/main.rs:4` 的 `__hook`、`__statusline`、`__daemon` 等子命令会在 GUI 初始化前运行；这些入口也必须解析到相同数据根目录。
- `src-tauri/src/bin/cli-manager-daemon.rs:25` 的独立 daemon 进程会自行解析数据根目录，不能只在 WebView 或主应用内保存路径。
- `src-tauri/src/hook_client.rs:255` 的 Hook 失败日志仍直接拼接 `<home>/.cli-manager/logs`，属于必须收口的数据路径旁路。
- `src-tauri/tauri.conf.json:55` 的桌宠资源访问 scope 仍硬编码 `$HOME/.cli-manager/pets/**`，自定义根目录时需要同步处理安全 scope，不能扩大到任意用户目录。
- 前端 `src/lib/appPaths.ts` 通过 `app_get_data_paths` 一次性缓存路径，SQLite 和 Store 随后使用该结果；运行中热切换会导致已打开句柄和缓存分叉，最小可靠方案应在重启后生效。
- 当前 `src-tauri/tauri.conf.json:65` 仅配置通用 bundle targets，没有 Windows 便携 ZIP 产物流程。
- GitNexus 影响分析结果：`GeneralSettingsPage` 为 CRITICAL（1 个直接调用方、41 条流程）；`getCliManagerDataPaths` 为 CRITICAL（8 个直接调用方、54 条流程）；更新下载分支为 LOW。实现必须保持现有 `app_get_data_paths` 返回字段兼容，并把新 UI 封装为通用页底部的独立区块，降低共享路径消费者的改动面。
- 当前 GitNexus Rust 符号索引不可用，Rust 发现清单由 App Data Persistence / App Startup / Tauri Updater 契约与精确调用搜索补齐。

## Scenario Matrix

- 安装版首次启动且无自定义配置：继续使用 `%USERPROFILE%\\.cli-manager`。
- 便携版首次启动：程序目录可写时使用约定的相对数据目录。
- 便携版位于只读目录：明确报错或要求选择可写目录，不静默改写用户目录。
- 自定义目录为空：初始化全新数据。
- 自定义目录已有完整 CLI-Manager 数据：直接使用，不覆盖。
- 自定义目录已有部分或损坏数据：明确诊断，禁止无提示合并。
- 自定义目录位于移动硬盘或网络盘且启动时不可用：阻止启动数据层并提示恢复路径选择。
- 便携程序与相对数据目录整体移动：新路径下继续使用原数据。
- 开发版与安装版并行：保持现有 `sessions.dev.json`、`history-cache-dev` 隔离规则。
- PTY daemon 已运行：切换根目录前必须停止旧 daemon，避免两个发现文件域并存。
- Claude/Codex Hook 已安装：Hook 入口能解析相同根目录；移动程序导致的外部 Hook 命令路径变化仍属于外部配置，不自动迁移。
- WSL、SSH、Worktree、分屏、窗口焦点和托盘状态：不改变数据根目录选择；外部运行环境的 `.cli-manager` 不纳入本功能。

## Acceptance Criteria

- [ ] Windows 便携版无需安装即可启动。
- [ ] 默认安装版未配置数据目录时仍使用 `%USERPROFILE%\\.cli-manager`。
- [ ] 便携模式将 CLI-Manager 数据全部保存在程序所在目录的 `data` 子目录内。
- [ ] 安装版和便携版均可在“设置 → 通用”页面底部选择自定义数据根目录，重启后仍使用该目录。
- [ ] 设置页不提供“切换到程序所在目录”；便携版恢复默认时自动回到程序旁的数据目录，安装版恢复默认时自动回到 `%USERPROFILE%\\.cli-manager`。
- [ ] SQLite 数据库及 `-wal`、`-shm` 文件、Store、日志、缓存、附件和备份均跟随选定根目录。
- [ ] `.claude`、`.codex`、WSL 与项目内数据路径不受影响。
- [ ] 复制便携程序和数据目录到新路径后可正常读取原配置与数据。
- [ ] 自定义目录无效或不可写时显示明确错误，不静默切换目录。
- [ ] 目标目录已有数据时不发生静默覆盖。
- [ ] 选择自定义目录后，用户可自主选择“迁移并重启”或“不迁移并重启”。
- [ ] 空目标目录可完整迁移当前数据；非空目标目录不提供自动迁移，不合并、不覆盖。
- [ ] 新增用户可见文案同时支持 `zh-CN` 与 `en-US`。
- [ ] 安装版运行时启动便携版，或便携版运行时启动安装版，只唤醒已有实例，不出现第二个应用进程。
- [ ] 存在终端或后台任务时无法执行数据目录迁移或切换，且不会自动终止任务。
- [ ] 便携版可检查新版本，但不会启动安装器；更新操作打开 Release 页面。
- [ ] 安装版更新流程保持现有行为。
- [ ] Release 同时发布 Windows x64 便携 ZIP，ZIP 内具备主程序、资源、辅助程序和便携标记。

## Out of Scope

- 迁移或管理 Claude、Codex、Pi 等外部 CLI 的配置和原始会话目录。
- 自动合并两个不同数据根目录中的数据。
- Windows ARM64 便携包。
- 擅自升级 Tauri、React、Rust 或其他依赖版本。
