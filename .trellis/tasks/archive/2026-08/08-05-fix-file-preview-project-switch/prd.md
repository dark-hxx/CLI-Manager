# 修复项目切换丢失文件预览

## Goal

修复文件浏览器在项目之间切换时清空文件预览标签、活动文件和未保存内容的问题。每个实际文件位置拥有独立的内存编辑工作区，切回项目后恢复原状态。

## Requirements

- 按实际文件位置隔离编辑状态：本地、WSL、Worktree 使用规范化路径；SSH 使用主机与远端根目录。
- 保留已打开文件、当前活动文件及未保存内容；项目切换不再提示会丢弃修改。
- 文件编辑器 Tab 明确关闭后清理对应工作区；同一文件位置仍有其他编辑器 Tab 时不得误清理。
- 状态仅保留到应用退出，不写入持久化存储。
- 异步文件打开、保存和路径跳转的结果必须归属发起项目，不能污染切换后的项目。
- 保持同文件位置的项目元数据更新不重载文件状态；保持远端文件上下文切换时的释放行为。

## Acceptance Criteria

- [ ] 项目 A 打开多个文件并产生未保存修改，切换项目 B 后再切回 A，标签顺序、活动文件和内容保持不变。
- [ ] 本地、WSL、SSH、Worktree、分屏和 Workspan 场景下项目状态互不串用。
- [ ] 快速切换时，进行中的打开/保存/跳转不会写入另一个项目。
- [ ] 关闭 dirty 文件编辑器 Tab 时仍显示统一确认；取消保留状态，确认后清理对应工作区。
- [ ] 关闭后重新打开该项目文件编辑器为空工作区；应用重启不恢复编辑状态。
- [ ] `npx tsc --noEmit` 和新增的定向回归测试通过。

## Technical Approach

- 在 `fileExplorerStore` 中增加按 `isSameProjectFileLocation` 匹配的内存工作区集合，活动项目继续使用现有字段作为兼容镜像。
- `openProject`/`closeProject` 负责快照与恢复；项目相关异步操作使用捕获的项目上下文做结果路由或失效检查。
- `TerminalTabs` 按目标编辑器项目聚合 dirty 文件；`terminalStore` 在编辑器生命周期结束时清理工作区。
- 不新增依赖、IPC、数据库结构或持久化配置。

## Out of Scope

- 跨应用重启恢复文件标签或草稿。
- 保存 Monaco 光标、选择区、滚动位置或 Markdown 预览模式。
- 修改文件树、SSH 文件传输或 Git Diff 的数据协议。
