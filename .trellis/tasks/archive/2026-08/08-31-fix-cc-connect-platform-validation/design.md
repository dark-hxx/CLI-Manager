# 技术设计

## 数据与状态规则

- `platform` 表示当前正在编辑的平台。
- `platforms[].enabled` 是平台是否参与连接和保存校验的唯一依据。
- 全新 Profile 的四个平台均为未启用；历史 Profile 继续由 Rust 的兼容逻辑迁移。
- 仅启用平台接受 allow_from 校验，未启用平台可以保留空白草稿。

## 前端

- 在远程连接设置中展示已启用平台摘要，摘要项可切换到对应平台。
- 保存失败时识别 Rust 返回的平台化 allow_from 错误码，并通过 i18n 显示平台名和失败原因。
- 不在前端复制各平台 ID 格式校验规则，格式判定继续以 Rust 为权威。

## Rust

- `normalize_profile` 在校验各启用平台时，将既有 allow_from 错误转换为稳定的平台化错误码。
- `normalize_allow_from` 的通用校验逻辑保持不变，避免影响微信授权解析和配置诊断等调用方。
- 增加覆盖四个平台、未启用草稿、历史迁移与多平台组合的测试。

## 兼容性

- 不修改持久化结构、IPC 请求结构或 cc-connect 配置格式。
- 已保存的多平台配置保持原样。
- 微信授权仍可临时隔离其他平台。
