# 技术设计

## 边界

- 前端负责模型映射草稿、获取按钮、加载/错误/空状态和模型候选选择。
- Rust Tauri command 负责网络请求、认证头、URL 规范化、超时、响应解析和错误码；密钥不回传、不写日志。
- 现有供应商保存接口不变，模型获取是无副作用查询。

## 数据流

1. 表单将 `appType`、Base URL、当前活动 Key、协议标记、完整 URL标记提交给 `provider_fetch_models`。
2. 后端按 app type 选择认证方式和 models endpoint：完整 URL启用时使用用户提供的完整 endpoint，否则追加该协议的标准 models 路径。
3. 后端仅返回去重后的模型 ID 列表和稳定错误码。
4. 前端将列表放入当前表单内存状态，选择后写入现有 `modelMappings` 草稿；保存仍由既有 provider create/update 完成。

## 兼容性

- API 格式/上游格式继续持久化为标记，不在本任务中执行网关路由或格式转换。
- `goalMode`、`remoteCompression` 旧字段继续读取和保留；控件不再暗示已经生效。
- 不复用公共模型价格同步接口。

## 风险与回滚

- 网络请求失败只影响表单获取，不影响已有供应商数据。
- 后端新增 command 可独立移除；前端获取按钮降级为手工输入。
- URL 和认证测试必须覆盖三类 app type，避免把某一种协议的路径规则套到其他类型。
