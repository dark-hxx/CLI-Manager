# 技术设计（用户已批准，版本 1.4.4）

## 基线与根因

- 分支：`fix/tap-transcript-performance`，基线 `ed788614`，同步远程 master 后创建。
- 根因陈述：Tap 的结构化对话以 PTY 输出为唤醒信号，固定延迟后走通用历史详情链路；读取、IPC 和渲染工作量没有限制在当前会话的增量，因此日志落盘时序与历史长度会放大可见延迟，应在 transcript 生产、调度和消费三层修复。
- `Conversation.tsx` 两处 2000ms 定时；请求期间只记 again，结束后还可能再等一轮。
- `executeTerminalTranscript` 强制 fresh，先请求完整 `HistorySessionDetail`，之后 `terminalTranscriptPage` 才裁剪到 40 条/512KiB。
- Rust fresh 分支绕过 V2 物化详情，详情扫描还包含工具和文件变更扫描；精确 Codex summary 查找也有目录枚举和候选文件解析开销。
- 每轮创建新的消息/轮次对象，未变化的历史与 hidden 工具详情仍参与渲染工作。

## 对外部分析的校正

- `forceCatalogRefresh` 只有精确查询未命中后才触发 refresh，不能说每次必定重建全量索引。
- `drainTerminalCommands` 与 `drainOperations` 已是不同通道，前者独立 75ms 调度；不能把管理操作串行等同于所有 PTY 输入/输出串行。
- 管理操作自身仍串行，transcript 与文件/Git/启动等读写管理操作可能互相等待。
- 第三方所述 Tap-Code 30ms 不是本项目实测性能承诺；日志尚未落盘时不可能读到其正文。

## 方案与边界

### 1. 主机侧轻量 transcript 读取

- 为 Web transcript 增加独立的只读实现，不修改通用历史详情接口的既有行为。
- 首次按现有授权根、来源、精确 CLI ID 和项目 cwd 解析会话文件；后续复用已验证定位，重新校验文件和当前绑定，失败不选择同目录其他会话。
- JSONL 建立有界增量状态：已处理字节位置、未完成尾行、解析上下文、revision、最近消息页；只保留实际需要的有界内容，不缓存整份原始日志。
- 沿用现有规范消息解析规则，保留明文 reasoning/tool call/result，禁止导出系统/metadata/密文。与全量规范结果做差分测试，不能另建一套不一致的聊天模型。
- 追加只处理新字节；未变化返回 unchanged/revision。截断、替换、检测到改写或解析版本改变时失效并重建；过长记录沿用明确截断/错误边界，不无界缓冲半行。
- 旧页显式读取，不在每次刷新中重复计算全部统计、用量与文件变更；既有最近页和旧页游标含义保持兼容。
- 缓存有数量、字节、空闲生命周期限制，并合并同文件并发读取；关闭、解绑和根配置改变失效，不为改善延迟引入新的内存放大。

### 2. 更新触发与传输

- 保持 `terminal.transcript` 的旧请求语义，增加能力协商后的 revision/增量响应；旧主机使用旧路径，不能对旧主机盲目提高重读频率。
- 复用现有认证、设备/会话范围与 WebSocket，不新建服务或独立 agent。活动订阅的日志变化通知只发送 revision/失效提示，正文仍经有界、精确校验的读取返回。
- 日志变化是更新依据，PTY 输出只作辅助唤醒；文件监听与低频、可取消的指纹兜底覆盖通知合并/丢失及延迟落盘。仅为已订阅会话保留这些工作，隐藏/离开时降频或解除。
- 活跃可见页约 400ms 合并，同会话单飞，期间变化合并为一次尾随读取；返回时 generation/binding 校验，重连重取快照，不自动重试输入。
- 只读 transcript 使用有界独立调度，不与慢管理写操作互相等待；不把所有 operation 改成无限并行，写操作维持原顺序。原生 terminal command/output 通道不重构。

### 3. 前端呈现

- 相同 revision/内容不 setMessages；稳定复用未变化的消息、旧轮次及工具推导结果，避免每次重算整段历史。
- 仅更新变化的轮次；对折叠工具详情按需计算/挂载，同时保留用户展开、搜索命中及阅读锚点行为。
- 不改页面样式、字体、原生终端几何或默认 renderer。原生彩色/文本重排单独记录帧与写队列指标，只有证据证明相关才扩大修复范围。

## 发现清单与预计影响

| 触点 | 结论 / 预计处理 |
| --- | --- |
| Tap Conversation / turns / activity / protocol / session scope | 更新调度、稳定引用、响应与订阅生命周期 |
| Web management / transcript projection | 主入口接轻量读取；保留 exact binding 的前后双重校验和有界导出 |
| WebDeviceBridge / polling | 只读调度隔离，维持 accepted/running/completion 状态机与去重 |
| Rust history parser / transcript sibling module | 复用规范解析，新增有界增量读取；不改历史统计业务语义 |
| Web device event / server relay / browser DTO | 如需增加 revision 通知，只做会话范围的兼容增量，不放宽账户或设备授权 |
| 普通 history API / catalog / 桌面历史 UI | 保持接口与结果；作为兼容性回归，不做全局缓存重构 |
| Native Terminal / PTY / renderer / ACK / 审批 / 输入 | 已确认与 2 秒 transcript 延迟非同链路；测量、回归，不先改行为 |
| 供应商 / 安装器 / 数据迁移 / SSH | 无本轮功能变更；WSL 使用既有访问边界，不用宿主 UNC 全树扫盘替代 |

GitNexus 工具未暴露；已在同步主干后刷新 codebase-memory，并用真实源码与领域契约复核。编辑前继续按具体符号检查调用方；涉及共享接口的高风险变更先报告，不以图谱结果替代源码。

## 风险、验证与回滚

- 主要风险是增量解析与全量语义不一致、重绑/断线旧响应泄漏、缓存失控、旧页偏移以及新增只读并发的状态竞争，必须有针对性测试。
- 用完全隔离的 Claude/Codex 合成日志比较同一输入下的旧/新结果；包含尾行分片、截断、替换、WSL 边界、重复通知、多端订阅与慢写操作。
- 分段测量“CLI 写入→主机增量完成→桥接完成→页面可见”，另测原生终端绘制，不混淆来源等待、网络 RTT 与解析时间。
- 以同一受控夹具的基线/优化后结果验收，不承诺所有设备 30ms，也不拿纯内存微基准冒充 Safari 实机结果。
- 保持旧接口快照回退与能力协商；如新增量路径异常，应明确失效并重取合法快照，不吞错或猜配会话。不涉及用户数据迁移，代码可整体回退。
