# 修复历史会话 Markdown 表格渲染与主题

## Goal

修复历史会话对“完整内容被 `md`/`markdown` 源码围栏包裹”的 Markdown 消息的展示：将其中的 GFM 表格直接渲染为表格，并让历史页普通 Markdown 代码块的容器、标题栏和边框跟随应用明暗主题。

根因陈述：历史会话链路 `SessionDetailPane -> SessionTranscriptContent -> HistoryMarkdownContent` 会把完整的 `markdown` 源码围栏作为普通代码块传给共享渲染器，未复用终端预览已有的顶层源码围栏解包逻辑；同时共享 Markdown 基础代码块容器和标题栏仍使用固定深色值，导致应用浅色主题下出现截图中的深色块。修复应落在历史 Markdown 适配层和共享 Markdown 的语义主题变量层，不修改后端历史解析契约。

## Requirements

- R1：抽取可复用的纯函数，识别并解包“整段内容仅由一个顶层 `md`/`markdown` 围栏组成”的源码；兼容 CRLF、反引号和波浪号围栏，保留不匹配、部分包裹、错误语言标记和嵌套代码围栏的原有代码语义。
- R2：历史会话的 `HistoryMarkdownContent` 仅在 history 变体使用该解包逻辑，然后交给现有 `MarkdownContent`/`remark-gfm` 渲染；保留 `SessionTranscriptContent` 的 XML、流程、Diff、长列表等特殊块识别，以及查询高亮、链接策略和安全配置。
- R3：共享 Markdown 默认代码块的背景、标题栏背景、边框和标题文字改用现有 `--md-*`/应用主题变量；默认代码语法配色继续随解析后的应用主题，终端变体继续使用其显式终端配色。
- R4：不新增依赖，不改 SQLite、Rust 历史命令、IPC、会话存储和消息内容；不改变其他 Markdown 消费方的解析语义。
- R5：补充针对源码围栏解包、历史渲染入口和主题回归的自动化检查，并同步更新 V1.3.9 `CHANGELOG.md` 与 `docs/功能清单.md`。

### 场景维度

- 应用主题：浅色、深色、跟随系统切换后的两种解析结果。
- 内容形态：裸 GFM 表格、完整 `markdown` 源码围栏、普通代码围栏、嵌套围栏、围栏前后混合文本、错误或未闭合围栏。
- 历史承载：单条消息、含特殊 transcript 块的消息、多条消息/多会话切换、历史详情与回放/终端预览共存。
- 运行环境：本地项目、WSL/Bash、Worktree、缺少 `.git` 或 `.git` 文件的项目只影响会话来源，不应改变本次纯前端渲染结果。
- 窗口与布局：窗口聚焦、失焦、分屏、最小化/托盘恢复，以及历史侧栏宽度记忆不应改变渲染结果。

## Out of Scope

- 不把所有 Markdown 代码块自动当成 Markdown 解析；只有完整顶层 `md`/`markdown` 源码围栏解包。
- 不调整终端预览的独立主题设置，不新增设置项。
- 不引入新的 Markdown 解析器或后端二次解析。

## Acceptance Criteria

- [x] 截图同类消息在历史会话中显示为真实 GFM 表格，不再显示 `MARKDOWN` 代码块外壳。
- [x] 普通代码围栏、嵌套代码围栏、未闭合/部分包裹/非 `md` 语言围栏仍按代码展示。
- [x] 历史页浅色主题下代码块容器不再固定深色，深色主题下对比度可读；切换主题后无需刷新即可使用对应变量。
- [x] 终端预览的显式代码主题和已有顶层 Markdown 围栏行为不回归，其他 Markdown 消费方行为不变。
- [x] `npx tsc --noEmit`、相关 Node 测试和生产构建通过；无后端/数据库/IPC 改动。
- [x] `CHANGELOG.md` 的 V1.3.9 条目和 `docs/功能清单.md` 的历史会话/Markdown 功能板块已准确记录。
